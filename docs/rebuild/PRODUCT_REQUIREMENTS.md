# 作る物の要件（PRODUCT_REQUIREMENTS）

2026-11-27。印：**【確】**＝出典を今回読んだ／**【般】**＝一般に知られた機能で、今回は公式の資料で確かめていない／**【推】**＝推測。

## 1. 目的と、目的でないもの

**目的**：1人の作り手が、kurzgesagt に迫る絵と動きの解説アニメを作れる環境。質が最優先。速さは質を落とさない範囲で上げる。工程ごとに「人がやる／一緒にやる／AI に任せる」を、いつでも切りかえられる。

**目的でないもの**（やらないと決めておく）：
- Illustrator・After Effects・Cinema 4D の全機能の再現。**ベクターの解説アニメに効くものだけ**。
- 本格的な 3D。奥行きは 2.5D（重ねた板とカメラ）まで。
- 複数人の同時編集。1人＋AI が前提。
- 実写の編集・色調整。

## 2. プロの道具から学ぶこと

### kurzgesagt の作り方【確】
- 絵は Illustrator、動きは After Effects。最近は Cinema 4D も試している。
- 1本あたり平均200枚ほどの絵を描き、**何百〜何千の部品**に分けて After Effects に持ちこむ。キャラクターには**リグ（骨組み）**を付ける。素材の棚はあるが、ほとんど毎回一から描く。
- 動く物はすべて手で動かしている。1本に約1,200時間。アニメは2〜3人で8〜12週間。
- 自分たちの講座では **60fps** で動かし、**式（エクスプレッション）**を使う作業の流れを教えている。

→ ここから言えること：質の源は「部品の多さ・リグ・手で付けた動き・式」。1人で近づくには、**同じ仕組み（部品・リグ・キーフレーム・式）をデータとして持ち、手間のかかる所を AI が肩代わりできる**ことが要る。1,200時間という量そのものには 1人では届かない。届かせる方法は「1場面あたりの濃さを保って、場面の数と長さを選ぶ」こと【推】。

### Illustrator から取り入れるもの【般】
| 機能 | なぜ要るか | 優先 |
|---|---|---|
| ペンツール（点と取っ手・なめらか／角） | 少ない点で洗練された形を作る土台 | 必須 |
| 図形（円・長丸・角丸・多角形）を数値で持つ | 図形的な部品。あとから角の丸みを変えられる | 必須 |
| 塗りと線を別に持つ・線の端の形・太さ | 光・口・すじを線で表す | 必須 |
| 形の合成（足す・くり抜く・重なりだけ） | 三日月・穴・口の中 | 高 |
| 色の一括管理（色に名前を付け、変えると全部変わる） | 場面ごとの色替え・絵柄の統一 | 高 |
| 部品のひな形と写し（1つ直すと全部変わる） | 群れ・草・使い回しても個体差を付ける | 高 |
| 左右対称・整列・等間隔 | 正面の顔・尾びれ | 中 |
| グラデーション・ぼかし | 水・空・光。使いすぎない | 中 |

### After Effects から取り入れるもの
| 機能 | なぜ要るか | 優先 |
|---|---|---|
| 形のレイヤー：図形を数値のまま持つ／自由な曲線、の2種類。形・塗り・線・加工を積み重ねる【確】 | 図形のまま動かせる（丸みや長さをキーフレームにできる） | 必須 |
| どの値にもキーフレームを打てる【確】 | 動きを人の手で直せる | 必須 |
| 速度のグラフ（イージングの曲線） | 動きの気持ちよさの大半はここ【般】 | 必須 |
| 親子づけ（親が動くと子がついてくる） | 今の parent と同じ考え | 必須 |
| 場面の入れ子（プリコンポーズ） | 「歩くカバ」を1つの部品として場面に置く【般】 | 必須 |
| 式（値を式で決める：くり返し・揺れ・ほかの値に連動）【確：形の値どうしを式でつなげる】 | 小さな動きを手で打たずに済む | 高 |
| 骨・IK・コントローラー（Duik が AE に足している物）【確】 | 手足を先端で動かす。歩き・まばたき・ばね・はずみの自動化もある | 高 |
| マスク・合成モード・トラックマット | 水面で切る・光を重ねる【般】 | 高 |
| カメラと奥行き | 手前をぼかす・ついていく・沈む | 高 |
| 形の加工（線を端から描く・ゆらす・くり返す）【確：パスの加工は塗りより先にかかる】 | 線が伸びる・波打つ | 中 |
| 動きのぼけ | 速い動きの自然さ | 中 |

### Cinema 4D（MoGraph）から取り入れる考え方【確】
- **クローナー**（物を並べて増やす）＋**エフェクター**（ばらつき・ずらし・時間差を与える）＋**フィールド**（効く範囲）。
- → 2D でも「草むら・群れ・泡・雨」を1つ1つ置かずに、**並べ方と、ばらつきの決まり**で作る。作り手の言う「使い回しに見えない」（大きさ・向き・色・時間をずらす）を仕組みにできる。
- 3D そのものは取り入れない。

### ほかの道具から【確】
- **Rive**：骨・制約・部品（入れ子）を1つのファイルに持ち、コードからも手からも直せる。AI が CLI で作り、人がエディタで整える流れを公式が打ち出している。→「同じデータを人と AI が触る」先例。ただし用途はアプリ向けの対話アニメで、書き出し先も独自形式。
- **Cavalry**：手続き的（決まりで作る）な 2D。個人は全機能が無料。→ エフェクター的な考えの 2D の先例。
- **Motion Canvas／Remotion**：コードで動画を書く。Motion Canvas は Canvas 1枚に命令で描く方式で、画面から時刻の印や値を触れる。Remotion は DOM を使い、会社で使うには有料。→ 今の制作室はこの系統（コードで描く）で、その弱みが今回の動機。
- **Lottie**：After Effects の動きを JSON にした形式。直線的に再生する用途向け。→ 取りこみ・書き出しの相手として考える価値はあるが、内部の形にはしない。

## 3. 機能の要件

優先の印：**M**＝無いと始まらない／**S**＝質に大きく効く／**C**＝あとでよい。

### 3.1 企画と進行
- M：題材 → 調べ → 構成 → 肉付け → 絵コンテ → 素材 → リグ → 動き → 合成 → 音 → 書き出し、の工程。工程ごとに状態（未着手・作業中・確認待ち・合格）と自動化の度合いを持つ。
- M：語りの文と場面のつながり（語りの言葉に絵の合図を結ぶ）。語りを直すと、合図の時刻が自動で付け直される。
- S：章ごと・場面ごとの確認と合格。合格した物は固定（勝手に変えられない）。
- S：決まり（部品・機械・読む）と、指摘帳・実物帳・手本帳。

### 3.2 ベクターの絵
- M：点と取っ手で形を描く・直す。図形を数値で持つ。塗り・線。重なり順・グループ・親子・付け根。
- M：少ない点への清書。なぞる下敷き。
- S：形の合成。色の一括管理。ひな形と写し。左右対称。
- S：手描き（ラスター）の絵を下敷きや質感として置ける。
- C：グラデーション・ぼかし・ざらつき。

### 3.3 リグ
- M：親子と付け根で回す。差し替え（口を開けた絵に入れ替える）。
- S：骨と IK。関節の曲げすぎ止め。形の変形（2つの形のあいだをなめらかに）。
- S：向きの違う絵（横・正面・斜め）を同じリグ名でそろえる。
- C：自動リグ（手足の型を当てる）。

### 3.4 動き
- M：どの値にもキーフレーム。速度のグラフ。時間の線（重ねて見る・ずらす・伸ばす）。
- M：場面の入れ子。くり返す動き（歩き・呼吸）を部品として持つ。
- S：式と、よく使う動きの部品（揺れ・くり返し・遅れてついてくる・ばね・はずみ・まばたき）。
- S：カメラ（動く・寄る・ついていく）と奥行き。場面のつなぎ。
- S：並べて増やす＋ばらつき（草・群れ・泡）。
- C：動きのぼけ。物理っぽい動き（水の輪など）。

### 3.5 素材と場面の管理
- M：素材の棚（部品・リグつきのキャラ・背景・動きの部品・色の組）。どの動画で使ったかが分かる。
- S：場面ごとに素材を変えた版（使い回しに見せない）。
- S：参考（実物・手本）を素材に結ぶ。

### 3.6 音と合成
- M：語り（今の声の仕組み）・効果音・BGM を時間の線に置く。−14 LUFS。
- S：字幕。エンディング。絵の合図に効果音を結ぶ。
- 当面は今の `voice.html`・`sound.html`・Python の混ぜ方を使い、あとで統合する。

### 3.7 自動化と AI（くわしくは AUTOMATION_DESIGN.md）
- M：工程ごとに 人が主導／一緒に／AI が主導 を、いつでも切りかえられる。同じ制作・同じデータのまま。
- M：AI のすることは全部「提案」か「記録つきの変更」。人はいつでも止める・直す・取り消す。
- M：AI は人と同じ操作（命令）しか使えない。
- S：AI が自分で確かめる（見直しループ）を、仕組みの中に持つ。

### 3.8 品質の点検と書き出し（くわしくは QUALITY_STANDARDS.md）
- M：損のない途中経過で書き出す。1080p 以上・60fps を選べる。
- M：下見（すぐ見られる）と本番（質を優先）が**同じ絵**になる。
- S：機械の点検（止まった画面・字の大きさ・はみ出し・色・点の数）。

## 4. 機能以外の要件

| 項目 | 要件 |
|---|---|
| 編集のやり直し | 変更は1つずつ記録し、どこまでも取り消せる。場面・素材・AI の変更も同じ仕組み |
| 壊さない編集 | 元のデータを残す。清書・合成・変形は、元に戻せる形で重ねる |
| 同じ結果 | 同じデータ＋同じ時刻 → いつでも同じ絵（乱数は種で固定）。下見と本番、人の画面と AI の環境で一致 |
| 速さ | 下見は 1080p の場面を止まらずに再生（目標 30fps 以上。要試作）。直した所だけ書き出し直す |
| 同期 | 人の手が要らない。端末の順番を考えなくてよい。新しいトークンを作らせない（今ある GitHub のトークンで動く）|
| データ | 1つの大きなファイルにしない。形の決まり（スキーマ）と検査を持つ。版の番号と、古い版からの移し替え |
| 端末 | 作る作業はパソコン（Mac・Chromebook）が主。スマホは確認・指摘・軽い直し |
| 使いやすさ | ボタンを押してもスクロール位置が戻らない。覚える操作を減らす。画面のどこを押すかが分かる |
| 置き場所 | GitHub Pages で動く。ファイルの張り替えを作り手にさせない |
| 続けやすさ | 部品ごとに試せる。1ファイルに固めない。記録を残す |
| 費用 | 月々の新しい契約を前提にしない（今の Claude と Gemini の範囲）|

## 5. 分かっていないこと・決めていないこと
- 1人でどこまでの量を作れるか（1場面の濃さと本数のつり合い）。
- ブラウザの Canvas で、目標の絵（ぼかし・合成・60fps）がどこまで出せるか → 試作で確かめる。
- 既存の道具（After Effects など）を AI が動かす案と、自前で作る案のどちらがよいか → SYSTEM_ARCHITECTURE.md で比べる。
