# 自動化の設計（AUTOMATION_DESIGN）

2026-11-27 改訂2。**案**。

**改訂2で変えたこと**：①度合い・許可・固定を、3つの別の物としてはっきり分けた ②3つとも、AI への指示文ではなく**命令の核が強制する**形にした ③提案が生きているかを、制作全体ではなく「提案が依りかかっている物」で決めるようにした ④AI の変更だけを取り消す方法を DATA_MODEL.md 9.5節に合わせた。

目的は自動化の割合を上げることではない。**最終の映像の質**のために、どの工程を誰がやるのが一番よいかを、いつでも選び直せるようにすること。

## 1. 3つの別の物

| 物 | 答える問い | 持つ所 | 例 |
|---|---|---|---|
| **度合い（Mode）** | だれが作るか | 工程ごと（場面ごとに上書き可）| 「動き（小）」は AI、「絵コンテ」は Collaborative |
| **許可（Permissions）** | AI は何を変えてよいか | 制作ごと（工程ごとに上書き可）| 色は変えてよい・消すのは不可 |
| **固定（Locks）** | この物は変えてよいか・先に聞くか | 部品・場面・値・語りの行ごと | 母カバの顔は `frozen`、背景の木は `ask` |

3つは互いに置きかえられない。度合いを「AI」にしても、許可が無い操作はできず、固定された物は動かない。固定を外しても、許可が増えるわけではない。

## 2. 度合い（Mode）

| 度合い | AI の命令は | 人のすること |
|---|---|---|
| **Human** | 文書に入らない。人が「手伝って」と頼んだ時だけ、その頼みに限って提案を出せる | 作る |
| **Collaborative** | すべて提案になる。採られた物だけが文書に入る | 見て、採る・一部だけ採る・直す・断る・方向を言う |
| **AI** | 許可の範囲で、文書にすぐ入る。固定 `ask` に当たる物だけ提案になる | あとから見る。いつでも止める・戻す・自分で直す |

- 3つは**同じ文書・同じ命令・同じ画面**の上で動く。切りかえても、やり直しや移し替えは起きない。
- **いつでも変えられる。作業の途中でも。** 度合いの変更も命令（`mode.set`）で、記録に残る。
- 切りかえの決まり：
  - AI の途中で人が同じ物を触ったら、その物は自動で Collaborative に落ちる（人の手が優先）。AI は続きを提案として出す。
  - AI → Human に変えたら、進行中の作業は区切りで止まり、やりかけは提案として残る（消さない）。
  - Human → AI に変えても、固定と許可はそのまま効く。
- 人はどの度合いでも、いつでも直接直せる。AI であることは、人の割りこみを妨げない。

## 3. 命令の核での強制

AI への指示文に「固定された物は触らないで」と書くだけでは守りにならない（読み違える・忘れる）。**命令の核が、当てる前に必ず検査する**（DATA_MODEL.md 9.3節の③）。

```
許しの検査（命令1つごと）
 送り主が人：
   固定 frozen に当たる → 断る（locked）。人は lock.remove で外してから直す＝うっかりを防ぐ
   それ以外 → 通す
 送り主が AI：
   種類が許可に無い（消す・表紙を変える 等）→ 断る（forbidden）
   固定 frozen に当たる → 断る（locked）
   前の段の物を作り替える → 提案に回す
   度合いが Human → 断る（頼まれた提案としてだけ出せる）
   度合いが Collaborative → 提案に回す
   度合いが AI で、固定 ask に当たる → 提案に回す
   度合いが AI で、どれにも当たらない → 通す
```

- 断りには理由の札が付く。AI の作業係は、札を見て出し直すか、止まって聞く。
- **記録を読むときも同じ検査を通す**（SYSTEM_ARCHITECTURE.md 3節）。だから、だれかが核を通さずに記録へ書き足しても、検査に通らない命令は、どの端末でも当たらない。
- 写し（`scenes/*.json`）を直接書きかえても、記録から作り直すので残らない。

> **書き直しの予定（2026-11-27）**：上の検査は、命令に書かれた送り主を見ている。これは送る側が自由に書けるので、権限は「名乗り」でなく「端末の署名の有無」で決める形に直す（SYSTEM_ARCHITECTURE.md 5b節。作り手の承認待ち）。下の「コミットの書き手で見分ける」案は、書き手を自由に指定できると分かったので**採らない**。

**正直な限界**：AI の作業係は、作業場からリポジトリに書ける。記録に「送り主は人」と偽って書くことは、仕組みの上では防ぎきれない。手当ての案は、「人の記録は、作り手のトークンで書かれたコミットにある物だけを人の物と認める」（GitHub のコミットの書き手で見分ける）。これが実際にできるかは P3 で確かめる【未】。

## 4. 許可（Permissions）

```
Perms = {
  write:    { 語り / 絵の形 / 色 / リグ / 動き / カメラ / 音 / 素材の棚 } それぞれ 可・提案のみ・不可
  create:   新しい部品・場面・素材を作ってよいか
  remove:   消してよいか（既定：不可。消したい物は「消す提案」）
  rules:    決まり・指摘帳（既定：足す提案だけ。書きかえ・削除は人）
  cover:    度合い・許可・固定そのものを変える（既定：不可。**AI は自分の許しを広げられない**）
  waive:    点検の警告を「意図あり」として通す札を付ける（既定：提案のみ）
  external: 書き出しの実行 / push / 公開　それぞれ 可・聞く・不可（公開は常に人）
  budget:   見直しの周の上限・1回の作業で変えてよい量
}
```

**どの度合い・どの許可でも変わらない決まり**
1. `frozen` の物は、AI は変えられない。
2. 前の段を作り替える変更は、AI は提案にしかできない（「段を分けて作る」）。
3. 消す・公開する・外へ送る・取り消せない操作は、人が決める。
4. AI は、度合い・許可・固定を自分で変えられない。
5. AI は命令の核を通る命令しか出せない。人の画面でできないことは AI にもできない。

## 5. 固定（Locks）

- `frozen`：変えられない。人も、外す命令（`lock.remove`）を先に出す。
- `ask`：AI は必ず提案にする。人はそのまま直せる。
- 相手：部品・場面・値の道（「この部品の色だけ」）・語りの行・素材。親を固定すると、中身にも効く。
- 作り手が「良い」と言った物は固定する（今の決まり「良いと言われた物は固定して1か所ずつ直す」）。合格の門を通った物も固定する（QUALITY_STANDARDS.md 4節）。
- 固定を付けた・外したことも記録に残る。外すときは理由をひとこと。

## 6. 提案と承認（Collaborative の中身）

1. AI は、命令のまとまり（提案）を作る。文書はまだ変わらない。
2. 提案に必ず付ける：**何を・なぜ**／**前と後の見本**／**機械の点検の結果**／どの決まり・指摘に基づくか／**依りかかっている物の一覧（`reads`）**。
3. 人は：**採る**／**一部だけ採る**（命令のまとまりごと）／**直してから採る**／**断る**（理由をひとこと。指摘帳の候補になる）／**方向を言う**（AI が出し直す）。
4. 採るときも、命令は核を通る（許し・前提・全体の決まりの検査をもう一度受ける）。

### 提案が今も生きているか
- 提案は、作った時に見ていた物を `reads` に書く：変える相手と、判断に使った物（親・色の組の色・合図のトークン・参照している値）を、**物ごとの版（rev）**で。
- 生きているかは、**`reads` の物が変わったかどうか**だけで決める。制作全体のハッシュや「何か1つでも変わったか」では決めない。
  - 関係のない部品・場面を人が直した → 提案はそのまま生きている。
  - `reads` の物が変わったが、提案が触る値の道とは重ならない → 生きている（核が当てる時にもう一度確かめる）。
  - 提案が触る値の道を人が変えた → その命令だけ `stale`。ほかの命令は生きている（一部だけ採れる）。
  - 判断に使った物が変わった（例：色の組が変わった）→ 「前提が変わった」と印を付けて見せる。採るかどうかは人が決める。
- `stale` になった分は、AI が今の文書で出し直す。古い提案を無理に当てない。

### 提案の大きさ
作り手の決まり「細部は1つ1つ」に合わせ、既定は小さく（1つの部品・1つの動き）。「まとめて」と言われた時だけ大きくする。案が複数あるときは並べて出す。

## 7. AI のときの流れ

今の「見直しループ／見直しのサイクル」を、仕組みの中身にする。

```
作る係 → 機械の点検 → 見る係（作る所を見ていない別の AI）→ 直す → …（上限 N 周）
                              ↓ 良くなったか分からない変更
                        前の版と2案を並べ、別の AI が選ぶ。負けたら戻す
```

- 作る係と見る係を分ける。
- 順番：ミスを直す → より自然に（実物帳と比べる）→ もっと良くする挑戦（手本帳と比べる）。挑戦が2回続けて負けたら止める。
- 区切りで止まり、報告する：何をしたか／前と後／迷った所／次にしたいこと。
- **迷ったら止まる**：決まりどうしがぶつかる・固定に当たる・取り消せない・質が下がったかもしれない。
- **AI は、点検の警告を自分で「意図あり」として通せない**（許可 `waive` の既定は提案のみ）。警告が残ったら、理由を添えて人に見せる。

## 8. 人の割りこみ

| したいこと | できること |
|---|---|
| 今すぐ止める | AI の作業は命令の区切りで止まる。途中の変更は残り、1つずつ見られる |
| 自分で直す | いつでも、どの度合いでも |
| ここは触るな | 固定する |
| 方向を変える | ひとこと指示を書く。AI は次の区切りから従う |
| 任せ方を変える | 度合い・許可を変える |

## 9. 取り消しと巻き戻し

- **1つ戻す**：ふつうの取り消し。
- **AI の変更だけを戻す**：AI の1回の作業（または命令1つ）を選んで戻す。**そのあとの人の直しは壊さない**。やり方は DATA_MODEL.md 9.5節：
  - 値の道ごとに見て、だれも触っていなければ戻す／人が上書きしていれば何もしない／動かした量なら AI の分だけ引く。
  - AI が足した物を人が直していた場合などは、**止まって聞く**（残すか、人の直しごと外すか。一緒に消える物を全部見せる）。
  - 戻す前と後の絵を並べて見せる。
- **この時点まで戻す**：場面・素材を、ある時点の状態に戻す。戻す前の状態も残る。
- **合格の印**：作り手が OK と言った時点に名前を付けて残す。
- 記録は足すだけで、消さない。

## 10. AI をどう動かすか

| 方法 | 今すぐ | 費用・鍵 |
|---|---|---|
| 会話で頼む（今と同じ）| できる | 今のまま |
| 予約タスク | できる（種の泉で実績あり）| 今のまま |
| アプリから直接 API | 新しい鍵と費用が要る | 作り手の約束に反する。今は採らない |

- 画面が「作業の札」（工程・場面・してほしいこと）を書き、作業係がそれを読んで、命令か提案を書き戻す。今の `jobs` と `WORKER.md` の発展形。
- 作業係は、命令の核を自分の環境で動かす（`check` で先に通るかを見る → 当てる → 下見を作る → 点検）。人の画面と同じ結果になる。
- 作業係には、その作業に要る決まりだけを渡す（今の `rules_for.py` の考え）。
- 作業係は、作り手のトークンを使わない（SYSTEM_ARCHITECTURE.md 5節）。

## 11. 工程ごとの既定（案）

初めの値。どれもいつでも変えられる。

| 工程 | 既定 | 理由 |
|---|---|---|
| 題材の候補・調べ | AI | 今も自動。選ぶのは人 |
| 構成・肉付け | Collaborative | 「案から良い所を残し、いらない所を削る」|
| 絵コンテ | Collaborative（つかみと山場は Human）| 「場面がいちばん大事」|
| 素材（絵）| Collaborative | 「細部は1つ1つ指示する」|
| リグ | AI | 判断が少なく、見て直せる |
| 動き（大）| Collaborative | 動きの質が一番難しい |
| 動き（小）| AI | 式と部品で付ける。量が多い |
| カメラ・つなぎ | Collaborative | 「カメラにも自分で手を加えたい」|
| 音 | Human → 学んだら AI へ | 「自分で置き、それを学習させる」|
| 題名・サムネ | Collaborative | |
| 点検・書き出し | AI（公開は人）| |
