## 2. 高品質なイラストの構造分析

**目的**：「洗練されている」を、作るときに使える**型紙**（数字の幅と手順）に直す。

**やり方**
1. 手本の絵を、絵としてではなく**作りとして**読む。見る項目を決めておく：
   - 部品：全部でいくつか／体・頭・脚がそれぞれ何枚の面か／重ね順
   - 輪郭：1つの部品の曲がり角（向きが大きく変わる所）がいくつか／直線に近い所と丸い所の割合／角はどこにあるか
   - 色：何色か／となり合う面の明るさの差／影と光を、別の面で置いているか・線で置いているか
   - 線：太さは体の大きさの何分の1か／何本か／端は丸いか
   - 比：頭と胴／目の大きさと頭／目の位置（頭の上から何割）
   - つなぎ：部品の境目を、重ねて隠しているか・切り抜いているか・線で区切っているか
2. 読んだ結果は、**言葉と数字だけ**を残す（手本帳の決まりのまま：画像は置かない・特定の絵を写さない）。
3. 同じ種類の絵を数枚読み、幅にまとめる。これが型紙。例：「体は 3〜5 面」「1部品の曲がり角は 2〜4」「線は 4〜8 本」「となり合う面の明るさの差は◯以上」。数字は読んでから決める【未】。

**今の制作室でできること**
- 手本帳にはすでに「やり方の言葉」が 30 行ほどある【確】（例：腹は背中と別の明るい面にする［絵9］、図形のままにしない［絵5］）。**足りないのは数字と、作る手順への落としこみ**。
- 手本帳の足し方（作り手の Chrome で止めた画面を、その場で見て言葉にする）がそのまま使える。見る項目を上の一覧にそろえるだけ。
- 自分たちの絵のほうは、`cap_parts.py`・P4 の JSON から、部品の数・点の数・色を機械で数えられる。

**新しい仕組みで要る物**：型紙を、素材の点検（QUALITY_STANDARDS.md 3.3節）の「警告」の基準として読める形で持つこと。題材の種類ごと（四つ足の動物、魚、木…）に1枚。

**確かめ方**：型紙あり・なしで同じ題材を作り、並べて選ぶ（9節 E2）。

## 3. 参考画像からのスタイル・形状・配色の抽出

**分けて考える。** 何から何を取るかで、やってよいことが違う。

| 取る物 | どこから | やり方 | 守ること |
|---|---|---|---|
| **形（比率・特徴）** | 実物の写真（実物帳 `docs/refs/jitsubutsu/`）| 目印の点を置く（鼻先・目・耳の付け根・肩・腰・ひざ・地面）。目印どうしの比を出す。影絵をなぞり、少ない点の曲線に当てはめる | 写真はなぞってよい。出来上がりは、そこから崩す |
| **崩し方** | 手本帳の言葉＋型紙 | 「どこを大きく・どこを省くか」を言葉で決める（例：鼻づらを 1.2 倍、脚を 0.8 倍、しわは 2 本まで）。倍率として持つ | 特定の絵の形はなぞらない |
| **配色** | 手本の傾向（明るさの段の数・あざやかさ）＋場面の色の決まり | 色そのものを写すのではなく、作り方を取る：ベース1色 → 少し明るい面 → 少し暗い面 → 線の色、の段と差 | 色の組は題材ごとに自分で作る |

**今の制作室でできること**
- 実物の写真に目印を置いて比を出すのは、Claude が画像を見て座標を書く形で、今すぐできる。精度は【未】（人が1回確かめる）。
- 影絵を少ない点の曲線に当てはめるのは、`parts.html` の清書（`fitPts`）と同じ計算が使える【確】。
- P4 の担当は、実物の比を測らずに作った【報】。まず測るだけで、「鼻づらが小さい」のような直しが1周めから消えるかを見る。

**新しい仕組みで要る物**：目印と比を、キャラクターの設計書（6節）に数字として持つこと。

**未確認**：崩し方の倍率を、言葉から決めてうまくいくか。作り手の好み（好み帳 `docs/refs/liked/`）とどう合わせるか。

## 4. 下書きと清書の分離

今の決まり「絵と動きは、段を分けて作る」（0 設計 → 1 大きな形 → 2 部品 → 3 細部）を、**1つの素材の中**にも当てる。P4 の担当は、いきなり部品を作った【報】。

| 段 | 作る物 | 見る物 | 止める条件 |
|---|---|---|---|
| A 比の箱 | 目印の点と、部品の大きさを表す箱だけ | 実物の比と合っているか（数字）| 比の外れが決めた幅の中 |
| B 影絵 | 全体を**1色で塗った1枚の形** | 黒い影絵だけで、何の動物か・どちら向きか分かるか | 見る係が、名前を伏せて当てられる |
| C 割る | 影絵を部品に割る（動く所で割る。7節）| 部品の数・重なり代・重ね順 | 関節を回してもすき間が出ない |
| D 清書 | 部品ごとに点を減らし、曲線を整える | 点の数・曲がり角の数・となりの部品とのつながり | 型紙の幅の中 |
| E 面と線 | 明るい面・暗い面・線を足す | 1部品1色・線の本数・明るさの差 | 型紙の幅の中 |

- **下書き（A〜C）は、点が多くても雑でもよい。** 見るのは比と読みやすさだけ。
- **清書（D）は別の係が、別の基準でやる。** 形は変えない。点を減らす・取っ手をそろえる・接する所の向きを合わせる、だけ。清書の前と後を重ねて、ずれが決めた幅を超えたら戻す。
- **後ろの段で前の段を作り替えない**（今の決まりのまま）。E の途中で比がおかしいと分かったら、A に戻して、そこから流し直す。
- B の「影絵で読めるか」は、P4 の担当が挙げた弱み（図形を並べた感じ）への、いちばん直接の手当て【推】。並べた図形は、1色で塗るとつなぎ目のへこみが目立つ。

**今の制作室でできること**：`"stage":N` で止めて描く・`stage_sheet.py` で段の一覧を出す仕組みがある【確】。素材づくり（`tools/kahitsu/`）に同じ止め方を入れればよい。影絵は、全部の部品を1色で描くだけ。

**新しい仕組みで要る物**：形の合成（影絵から部品を切り出す・部品をつないで1つの輪郭にする）と、親の形での切り抜き。P1 が CanvasKit に決まれば、その機能が使える【報】。**決まるまで、ここは作らない。**

## 5. 別の AI による品質評価と修正提案

今ある「見直しループ」（`tools/REVIEW.md`・`review_sheets.py`・指摘帳）は、場面の絵と動きが相手。**素材1つ**にも同じ形で当てる。P4 の担当は、これを使っていない【報】。

**係を3つに分ける**
| 係 | 見る物 | 渡さない物 | 返す物 |
|---|---|---|---|
| 作る係 | 目標・型紙・設計書・前の周の指摘 | — | 絵と、段ごとの一覧 |
| 見る係 | 出来た絵（影絵・点つき・仕上がり）・目標・型紙・実物の写真・手本帳の当てはまる行 | **作った理由・作る係の自己評価** | 項目ごとの点と、直しの提案 |
| 選ぶ係 | 前の版と今の版を、どちらが新しいか伏せて並べた物 | どちらが新しいか・何を直したか | どちらが良いか、理由1行 |

**見る係の返し方（決める）**
- 項目は目標の項目（P4 の `GOAL.md` の 11 個のような、見て確かめられる文）。項目ごとに点。
- 直しの提案は、**場所と向きと量**まで書く：「頭・鼻先の上の点を、右上へ、頭の幅の 5% ほど」。「もっとカバらしく」は返さない。← 新しい仕組みでは、これがそのまま命令（`pt.nudge`）の提案になる。
- 1周で直すのは、**重い物から 3 つまで**。全部を一度に直すと、どれが効いたか分からない。
- 何段めの話かを必ず付ける（比＝A、影絵＝B…）。A・B の指摘が残っているうちは、D・E の指摘を直さない。

**見る係を信じてよいかを測る（大事）**
- AI の見る係は、AI の絵に甘いかもしれない【推】。P4 の担当の自己評価（2〜3）と、作り手の評価のずれが、最初の手がかりになる。
- **作り手の「評価.json」が届いたら**：同じ3つの絵を、何も知らない見る係に同じ項目で採点させ、作り手の点との差を項目ごとに出す。差が大きい項目は、見る係に任せず、作り手が見る項目として残す。
- 作り手の点とひとことは、見る係に渡す「採点の見本」にする（この絵のこの項目は 2、理由はこう）。

**今の制作室でできること**：全部。別の Claude に見せる手順も、2案を並べて選ぶ道具（`loop2.py`）もある【確】。素材用の渡し方を1つ決めるだけ。

## 6. キャラクターの一貫性を保つ仕組み

**キャラクターの設計書**を、素材ごとに1つ持つ（言葉と数字。絵そのものではない）。

```
設計書（例：母カバ）
  比      ：目印どうしの比（頭/胴、脚の長さ/胴の高さ、目の位置 …）と、許す幅
  色の組  ：ベース・明るい面・暗い面・腹・線・目。名前で持つ
  部品の表：名前・親・付け根・重ね順・何色か（7節の割り方）
  線      ：太さ（体の高さの何分の1）・本数の上限・どこに入れるか
  顔      ：目の形と大きさ・口の線の形・表情ごとの差し替え
  向き    ：横・斜め・正面。向きごとに、変わる部品と変わらない部品
  決まり  ：このキャラクターだけの指摘（「笑った口にしない」など）
```

- 場面で使うのは、設計書から作った**ひな形の写し**（DATA_MODEL.md 4節の `instance`）。場面ごとに描き直さない。場面で変えてよいのは、設計書が「変えてよい」とした所（ポーズ・表情・色の染まり）だけ。
- **機械の点検**：場面の中の写しを設計書と比べ、比・色・線の太さが幅を外れていたら警告。
- 子カバのような「同じ種類の別のキャラクター」は、母の設計書から比だけを変えて作る（頭を大きく・脚を短く、の倍率）。別々に一から作らない。
- 作り手が「良い」と言った部品は固定する（今の決まり）。直すときは1か所ずつ。

**今の制作室でできること**：`tools/kahitsu/packs/*.json`（部品の束）と `sozai_kimari.md` がある【確】。設計書は、束の隣に置く文書として今すぐ書ける。点検は、束の JSON から比と色を数える小さな道具で足りる（今は無い）。

**未確認**：向きを変えたとき（横 → 斜め）に、どこまで同じ部品を使い回せるか。

## 7. アニメーションを前提としたパーツ分割

**動きから逆に割る。** 見た目で割ると、動かす段で割り直しになる。

1. **動きの表を先に書く**：このキャラクターが、この動画でする動き（歩く・口を開ける・耳を振る・まばたき・水に沈む…）。
2. **動きごとに、回る所（付け根）を決める**。付け根の数だけ部品が要る。動かない所は割らない（部品を増やさない）。
3. **重なり代を付ける**：回る部品は、付け根の向こうへ丸く伸ばしておく（回してもすき間が出ないように）。重ね順は、隠したい側を下に。
4. **形が変わる所は、点を動かす部品にする**（口・まぶた・腹のふくらみ）。点の数を、変わる前と後でそろえておく。
5. **差し替える所を決める**（目の開け閉め、口の形）。

**機械の点検（割ったあと、動かす前に）**
- 付け根ごとに、決めた角度の幅で回して描き、**すき間（背景が見える画素）と、はみ出し**を数える。
- 回した時に、重ね順がおかしく見える所（奥の脚が手前に出る、など）を一覧の画像で見る。
- 部品の数が、動きの表から数えた数より多ければ、割りすぎ。

**今の制作室でできること**：`parts.html` の部品は付け根（`joint`）と親（`parent`）を持ち、`render_parts.py` で描ける【確】。回して描いて一覧にする道具を足せば、点検はできる（今は無い）。

**新しい仕組みで要る物**：リグ（DATA_MODEL.md 5節）と、この点検を素材の合格の門に入れること。

## 8. 品質を評価する基準と、反復して良くする仕組み

**基準を2種類に分ける**（QUALITY_STANDARDS.md の「確かめ方」に合わせる）

| 機械で測る | 読む（見る係・作り手）|
|---|---|
| 部品の数・1部品の点の数・色の数 | 実物の特徴を捉えているか |
| 曲がり角の数・輪郭の折れ（となりの取っ手の向きのずれ）| キャラクターっぽくしすぎていないか |
| 部品どうしのすき間・意図しないはみ出し | 少しかわいいか・不快感がないか |
| となり合う面の明るさの差 | 図形を並べた感じが残っていないか |
| 設計書の比・色・線の太さからの外れ（6節）| 手本と並べて見劣りしないか |
| 関節を回したときのすき間（7節）| |
| 影絵にしたときの、輪郭のへこみの数（4節 B）【未：測り方を決める】| |

- 機械の項目は、合格の線を数字で持つ。**線は、作り手の評価が届いてから決める**（作り手が良いと言った絵・悪いと言った絵の数字を並べて決める）。先に勝手に決めない。
- 読む項目は、見る係の点を使う。ただし 5節の「ずれ」を測った項目だけ。

**回し方**（今の「見直しのサイクル」と同じ順）
```
段ごとに：作る → 機械の点検 → 見る係 → 重い物から3つ直す → 選ぶ係が前の版と比べる
  勝ち → その版を固定して次の指摘へ
  負け → 戻す。同じ指摘で2回負けたら、その指摘は作り手に回す
段の合格 → 次の段へ（前の段は作り替えない）
```
- 順番：ミスを直す → 自然に（実物帳と比べる）→ 挑戦（手本帳・型紙と比べる）。挑戦が2回続けて負けたら止める。
- **周ごとに残す物**：点つきの一覧の画像・機械の数字・見る係の点・選ぶ係の結果。あとで「どの手当てが効いたか」を数えるため。
- **作り手に見せるのは、段の合格のあとだけ**。作り手の指摘は、指摘帳と設計書の「決まり」に足す。同じ指摘を2度させない。
- **止める条件**：上限の周／選ぶ係に2回続けて負けた／機械の数字が良くなっているのに見る係の点が動かない（＝物差しが足りない。作り手に見せる）。

**質が上がったかの測り方**：同じ題材（母カバ）・同じ目標で、手当てを1つずつ足した版を作り、P4 の3つの絵（人のみ・下組み＋人・AI のみ）と並べる。作り手の点が、P4 の AI のみを超えるか。

| # | 実験 | 手当てする見立て | 要る物 | 作り手の手 |
|---|---|---|---|---|
| E1 | **型紙づくり**：手本帳の「絵の作り全般」に、2節の項目で数字を足す。四つ足の動物の型紙を1枚 | a | 手本を見る手段（作り手の Chrome）| 動画を開いてもらう |
| E2 | **母カバの作り直し**：実物の比を測る（3節）→ 段 A〜E で作る（4節）→ 別の Claude が見る・選ぶ（5節）。P4 の AI のみと、同じ目標で並べる | b・c・d | P4 の絵の形（JSON）と描き方をそのまま借りる | 並べた絵を見て点を付ける |

- **やらないこと**：新しい描く画面・形の合成の実装・絵を作る別の AI サービスの組みこみ。最後の物は、検討の対象には入れてよいが（外部の物を使うこと自体は方針に反しない）、ベクターの部品・少ない点・動かせる割り方、という条件に合う物があるかは調べていない【未】。

## 10. P4 の評価が届いたら、ここで決めること

- 「人のみ」「下組み＋人」「AI のみ」の点の差 → AI に任せる範囲（下組みまでか、清書までか、仕上げまでか）。
- 作り手が下組みのどこを直したか（操作の記録）→ 下組みで AI が間違えやすい所の一覧 → 設計書と型紙に足す。
- 見る係のずれ（E3）→ どの項目を AI の見る係に任せ、どの項目を作り手が見るか。
- 作り手のひとこと → 機械で測る項目に直せる物があるか。
