# 品質の基準（QUALITY_STANDARDS）

2026-11-27 改訂2。**案**。数字は初めの置き値（「要調整」）。作り手が決めたことは（作り手）と書く。

**改訂2で変えたこと**：基準を「必須・警告・推奨」の3つに分けた。前の版は、止まった画面・点の数・小さな動きなどを、どれも合否の条件のように書いていた。意図した静止や余白も表現なので、それらは**警告か推奨**に下げ、意図の札を付ければ通るようにした。

## 1. 考え方

- 基準は、表現のしかたを固定するための物ではない。**最終の映像の質を上げるために、見落としを減らし、人の目を判断の要る所に集める**ための物。
- **機械が合否を決められるのは、「壊れている」ことだけ。**「良い絵か・良い動きか」は、機械は気づかせるだけで、決めるのは人。
- 手本（kurzgesagt の分析）と実物に並べて判断する。

## 2. 3つの重さ

| 重さ | 意味 | 通し方 |
|---|---|---|
| **必須** | 破ると、映像が壊れる・事実や約束に反する・あとで直せなくなる | 直すまで先へ進めない。意図で通すことはできない |
| **警告** | 質を下げていることが多いが、意図した表現のこともある | **意図の札**（何を・なぜ）を付ければ通る。札を付けるのは人（AI は「付けてほしい」と提案するだけ）|
| **推奨** | 質を上げる手がかり | 知らせるだけ。何もしなくてよい |

- 意図の札は部品・場面に残る（DATA_MODEL.md 4節の `intent`）。あとから「なぜここは止まっているのか」が分かる。
- 同じ警告に何度も札を付けているなら、基準のほうが合っていない。基準を直す。
- 警告と推奨の線は、実際の場面で使いながら動かす。必須に上げるのは、破ると必ず困ると分かった物だけ。

## 3. 工程ごとの基準

確かめ方の「機械」＝プログラムが見る、「読む」＝人か見る係の AI が見る。

### 3.1 調べ・構成・肉付け
| 重さ | 基準 | 確かめ方 |
|---|---|---|
| 必須 | 事実に出どころがある。「要確認」が残っていない（作り手）| 機械＋読む |
| 必須 | 著作物の文章をそのまま写していない・実在の有名人の写真を使っていない（今の約束）| 読む |
| 必須 | 争い・事故は、どちらが悪いと決めつけない。疑いの段階の話を入れない（作り手）| 読む |
| 警告 | 語りの速さが 1秒あたり約8字から大きく外れる（作り手）| 機械 |
| 警告 | 比べる相手を先に予告している・差し込みから戻る合図が無い（作り手）| 読む |
| 推奨 | 冒頭に問いと答えの気配（今の型紙）。オチが印象に残る（作り手）| 読む |

### 3.2 絵コンテ
| 重さ | 基準 | 確かめ方 |
|---|---|---|
| 必須 | 場面ごとに、見せる物と前後のつなぎが決まっている | 機械（設計表の空欄）|
| 警告 | 同じ構図が長く続く（作り手）| 機械＋読む |
| 警告 | 1つの場面の情報量が多い（作り手）| 読む |
| 推奨 | 切り替えでなく、主役の動きにカメラがついていく（作り手）| 読む |
| 推奨 | 見ていて楽しい演出（作り手）| 読む |

### 3.3 素材（絵）
| 重さ | 基準 | 確かめ方 |
|---|---|---|
| 必須 | 切れた参照・名前のない部品・付け根のないリグの部品が無い | 機械 |
| 必須 | 使う字が `library/fonts/` にある | 機械 |
| 警告 | 1つの部品の点が多い（12個を超える）。**下限は無い**。少ない点で形が決まっているほうがよい（作り手）| 機械 |
| 警告 | 色の組に無い色を使っている | 機械 |
| 警告 | 重なる部品どうしの色が近く、形が読めない（作り手）| 機械（要調整）|
| 警告 | 同じ素材の写しが、ばらつきなしで並んでいる（作り手）| 機械 |
| 推奨 | 図形から作る。光と影は別の部品。光・口・すじは線（作り手）| 読む |
| 推奨 | キャラクターっぽくしすぎない・図形的すぎない絶妙な形（作り手）| 読む（実物帳・手本帳と並べる）|
| 推奨 | 要る向き（横・正面・斜め）がそろっている（作り手）| 読む |

### 3.4 リグ
| 重さ | 基準 | 確かめ方 |
|---|---|---|
| 必須 | つまみを端から端まで動かしても、計算が壊れない（数でない値が出ない）| 機械 |
| 警告 | 動かすと部品のあいだにすき間・はみ出しが出る | 機械 |
| 警告 | 関節が逆に曲がる | 機械 |
| 推奨 | つまみ・差し替えの名前が、向きが違っても同じ | 機械 |

### 3.5 動き
| 重さ | 基準 | 確かめ方 |
|---|---|---|
| 必須 | 宙に浮いた合図（語りのトークンが消えた鍵）が無い | 機械 |
| 必須 | 式が上限を越えていない・数でない値を出していない | 機械 |
| 警告 | **画面がほとんど変わらない時間が続く**（作り手：切り替えで間を作らない）。意図した静止は、札を付けて通す | 機械（今の `lint_shots.py` の考え）|
| 警告 | 動きが語りより後に終わる（作り手）| 機械 |
| 警告 | 鍵と鍵のあいだが等速のまま（機械的に見えやすい）。意図した等速（流れる物・回る物）は札で通す | 機械 |
| 警告 | 多くの物が同じコマで動き始める | 機械 |
| 推奨 | 主役に小さな動き（呼吸・まばたき・揺れ）がある。**いつも動かす必要はない** | 機械が知らせる |
| 推奨 | 生き物の動きが実物らしい。動きに理由がある（作り手）| 読む（実物の動画と並べる）|

### 3.6 カメラ・合成
| 重さ | 基準 | 確かめ方 |
|---|---|---|
| 警告 | つなぎの前後で、目を引く場所が大きく飛ぶ（作り手の観察）| 機械（要調整）＋読む |
| 警告 | 字が小さい・安全な範囲の外にある | 機械 |
| 推奨 | 背景もレイヤーに分けて奥行きを出す。手前の物のふちに光（作り手）| 読む |
| 推奨 | 移動したら景色が変わる（作り手）| 読む |

### 3.7 音
| 重さ | 基準 | 確かめ方 |
|---|---|---|
| 必須 | クレジット「VOICEVOX:青山龍星」がある（作り手）| 機械 |
| 必須 | 音が割れていない・語りが途切れていない | 機械 |
| 警告 | 全体の大きさが −14 LUFS 前後から外れる（作り手）| 機械 |
| 警告 | BGM が声に対して大きすぎる・小さすぎる（作り手：スマホで聞いて確かめる）| 機械＋読む |
| 警告 | 読み間違いの疑い | 機械（辞書）＋読む |

### 3.8 描画と書き出し
| 重さ | 基準 | 確かめ方 |
|---|---|---|
| 必須 | **「本番どおりに見る」の絵と、書き出した絵が一致する**（SYSTEM_ARCHITECTURE.md 4節の差の試し）| 機械 |
| 必須 | コマ落ち・真っ黒なコマ・音と絵のずれが無い。長さ・大きさ・fps が設定どおり | 機械 |
| 必須 | 途中で損のある圧縮を挟んでいない | 流れそのもので守る |
| 警告 | 平らな色に帯・にじみが出ている | 機械（要調整）＋読む |

## 4. 合格の門

| 門 | 通る条件 | 通すのは |
|---|---|---|
| 構成 → 絵コンテ | 必須が全部通る＋作り手が構成を OK | 人 |
| 絵コンテ → 素材 | 必須が全部通る＋作り手が下絵を選んだ | 人 |
| 段ごと（1大きな形 → … → 6仕上げ）| 必須が全部通る＋警告は「直した」か「意図の札あり」＋（Human・Collaborative なら）作り手の OK | 度合いによる |
| 章 → 次の章 | 章を通しで見て作り手が OK（作り手：1章ずつ確かめる）| **必ず人** |
| 本番の書き出し → 公開 | 3.7・3.8 の必須が全部通る＋作り手が見た | **必ず人** |

- 推奨は門の条件にしない。
- 門を通った物は固定する（AUTOMATION_DESIGN.md 5節）。
- 度合いが AI でも、警告を自分で通すことはできない。残った警告は、理由を添えて人に見せる。

## 5. 見直しのやり方

- **見る係は、作る所を見ていない別の AI**。渡すのは：出来た物・当てはまる決まり・指摘帳・実物帳と手本帳の当てはまる所。作った理由は渡さない。
- 見る観点（作り手）：①ミスはないか ②自然に見えるか ③見ていて心地いいか ④さらに良くするには。
- 「良くなったか」は前の版と並べて決める。並べずに「良くなった」と言わない。
- 作り手の新しい指摘は、必ず指摘帳に足す。同じ指摘を2度させない。
- 指摘が決まりに育ったら、**重さ（必須・警告・推奨）と確かめ方（部品に入れる・機械・読む）を決めてしまう**。今の「決まりの3段」（部品・機械・読む）は確かめ方の分け方で、重さとは別の軸として両方持つ。

## 6. 点検の道具（作る物）

| 道具 | 見る物 | 今ある土台 |
|---|---|---|
| 文書の検査 | 形の決まり・切れた参照・宙に浮いた合図・式の上限 | なし。命令の核の「全体の決まり」と同じ物を使う |
| 絵の点検 | 点の数・色の組・重なりの色・使い回し | `sozai_kimari.md` |
| 動きの点検 | 変わらない時間・等速・同時の動き・語りとのずれ | `lint_shots.py` |
| 構図の点検 | 補助線・目を引く場所・つなぎ | `scene_measure.py`・`composition.md` |
| 描画の差の試し | 下見と書き出しの画素の差 | なし（P1 で作る）|
| 書き出しの点検 | コマ・長さ・音量・黒い画面 | `final_export.py` の確かめ |
| 一覧の画像 | 段ごと・版ごとを1枚に | `stage_sheet.py`・`review_sheets.py` |

結果の形：`{ check, 重さ:'must'|'warn'|'info', 対象, 結果:'ok'|'hit', 値, 基準, 見本, intent? }`。提案にも門にも同じ形で付く。

## 7. 質が上がったかを測る

- 作り手が1場面に出す指摘の数・同じ指摘のくり返し。
- 意図の札の数と中身（どの警告が、よく通されているか → 基準の見直し）。
- 1場面にかかる作り手の時間。
- 公開後の数字（視聴維持率。とくに場面の切り替わり）。
- 節目ごとに、同じ題材の1場面を作って手本と並べる。

## 8. まだ決めていないこと
- 「要調整」と書いた数字の全部。
- 色の近さ・目を引く場所を、機械でどこまで当てられるか。
- 警告が多すぎて読まれなくなる心配。まず少ない数で始める。
