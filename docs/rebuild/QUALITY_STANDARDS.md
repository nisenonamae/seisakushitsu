# 品質の基準（QUALITY_STANDARDS）

2026-11-27。**案**。数字の多くは初めの置き値で、実際の場面で確かめて直す（「要調整」と書いた所）。作り手がこれまでに決めたことは、出どころを（作り手）と書く。

## 1. 考え方

- **3つの段で守る**（作り手・2026-11-21 の決まりをそのまま使う）：
  - **部品**：道具の既定に入れてしまう（破りようがない）。
  - **機械**：プログラムが点検する。
  - **読む**：判断が要る。人か、見る係の AI が見る。
- **早い所で止める**：語りの間違いを動きの段で見つけても遅い。工程ごとに「合格の門」を置き、通ってから次へ。
- **人の目が最後**：機械と AI の点検は、人の時間を「判断が要る所」に集めるためにある。合格を出すのは作り手。
- **手本と実物に照らす**：良し悪しは、手本帳（kurzgesagt の分析）と実物帳に並べて決める。

## 2. 工程ごとの基準と確かめ方

### 2.1 調べ・構成・肉付け
| 基準 | 段 | 確かめ方 |
|---|---|---|
| 事実には出どころがある。食い違う年・数は言わないか幅で言う（作り手） | 読む | 見る係が出どころと照らす。「要確認」が残っていないか機械で探す |
| 冒頭15秒に問いと答えの気配（今の型紙 `STYLE_DEFAULT`）。オチは印象に残る（作り手） | 読む | 型紙と照らす |
| 比べる相手は予告しない・差し込みから戻るときは言葉と絵の両方で（作り手） | 読む | |
| 語りの速さ 1秒あたり約8字（作り手） | 機械 | 文字数と秒数から計算 |
| 時事政治・医療健康は扱わない（CLAUDE.md の方向）。争い・事故は両方の立場を並べる（作り手） | 読む | |

### 2.2 絵コンテ（場面の設計）
| 基準 | 段 | 確かめ方 |
|---|---|---|
| 場面ごとに：見せる物・構図・カメラ・前後のつなぎが決まっている | 機械 | 設計表の空欄を探す |
| 同じ構図が続かない（正面・上から・寄りを差しこむ）（作り手） | 機械＋読む | 構図の札の並びを見る |
| 情報量が多すぎない（作り手：「水辺はカバと景色だけでよい」） | 読む | |
| 切り替えでなく、主役の動きにカメラがついていく（作り手） | 読む | |
| 見ていて楽しい演出がある（作り手） | 読む | 人が見る |

### 2.3 素材（絵）
| 基準 | 段 | 確かめ方 |
|---|---|---|
| 図形から作る。1つの部品は点 4〜8個（複雑な胴でも12まで）（作り手・`sozai_kimari.md`） | 部品＋機械 | 道具の既定を図形に。点の数を数える |
| 1つの部品は1色。光と影は別の部品を重ねる | 部品 | 塗りは1色が既定 |
| 光・口・すじは線の部品 | 読む | |
| 重なる部品に同じ色がかぶらない（作り手） | 機械 | 重なる部品どうしの色の差を計算（差の下限は要調整）|
| 色は色の組から選ぶ（組にない色を使わない） | 部品＋機械 | 色を名前で指す。名前のない色を探す |
| キャラクターっぽくしすぎない。実物の特徴を捉える（作り手） | 読む | 実物帳と並べる |
| 図形的すぎない絶妙な形（作り手：「顔も体もどこか円形」はだめ） | 読む | 手本帳と並べる |
| 素材を使い回しすぎない。木には大小の個性（作り手） | 機械＋読む | 同じ素材の写しの数と、ばらつきの有無を数える |
| 部品に名前・親子・付け根が付いている | 機械 | 名前なし・親なしを探す |
| どの向きでも描ける（横・正面・斜め）（作り手） | 読む | 要る向きがそろっているか |

### 2.4 リグ
| 基準 | 段 | 確かめ方 |
|---|---|---|
| 付け根で回しても、すき間・はみ出しが出ない | 機械 | つまみを端から端まで動かして、部品のあいだのすき間を測る |
| 関節が逆に曲がらない | 部品 | 曲げる範囲を持つ |
| つまみ・差し替えに名前がある。向きが違っても同じ名前 | 機械 | |

### 2.5 動き
| 基準 | 段 | 確かめ方 |
|---|---|---|
| 止まった画面で待たない。字幕がずっと続くテンポ（作り手） | 機械 | 画面の変化が小さい時間を測る（今の `lint_shots.py` の考え）|
| 動きは語りの中で終わる | 機械 | 動きの終わりと語りの終わりを比べる |
| 等速で動かない（始まりと終わりに緩急） | 部品＋機械 | 既定の速度の曲線を緩急つきに。直線のままの鍵を探す |
| 生き物の動きが機械的・単調でない（作り手） | 読む | 実物の動画と並べる |
| 動きに理由がある（群れに合流する、など筋を省かない）（作り手） | 読む | |
| 水の輪などは、動いているときだけ（作り手） | 読む | |
| 小さな動き（呼吸・まばたき・揺れ）が止まっていない | 機械 | 主役がまったく動かない時間を測る |
| 時間をずらす（全部が同時に動かない） | 機械 | 同じコマに始まる動きの数を数える |

### 2.6 カメラ・合成
| 基準 | 段 | 確かめ方 |
|---|---|---|
| 目線が飛ばない（つなぎの前後で、見る場所が近い）（作り手：kurzgesagt の観察） | 機械＋読む | つなぎの前後の「目を引く場所」の距離を測る（今の `scene_measure.py` の考え。要調整）|
| 背景もレイヤー分けして奥行きを出す（作り手） | 機械 | 奥行きの段の数を数える |
| 手前の物のふちに光（近くで見ている実感）。光はむやみに入れない（作り手） | 読む | |
| 移動したら景色が変わる（背景を使い回さない）（作り手） | 読む | |
| 字が小さすぎない・端で切れない | 機械 | 字の高さと安全な範囲 |

### 2.7 音
| 基準 | 段 | 確かめ方 |
|---|---|---|
| 全体 −14 LUFS 前後（作り手） | 機械 | 測る |
| BGM は声の基準より少し大きめ。スマホで大きすぎない（作り手） | 機械＋読む | 声と BGM の差を測る。スマホで聞く |
| 読み間違いがない | 機械＋読む | 辞書と `kana` で確かめる（今のやり方）|
| クレジット「VOICEVOX:青山龍星」がある（作り手） | 機械 | |

### 2.8 書き出し
| 基準 | 段 | 確かめ方 |
|---|---|---|
| 下見と本番が同じ絵 | 機械 | 同じ時刻のコマを比べる |
| 途中で損のある圧縮をしない | 部品 | 書き出しの流れを損のない形に |
| 1080p 以上。fps は場面の設定どおり（60 か 30） | 機械 | 出来た動画を調べる |
| コマ落ち・真っ黒・音ずれがない | 機械 | コマの数・長さ・黒い画面・声と字幕の時刻 |
| 平らな色に帯やにじみが出ていない | 機械＋読む | 拡大して見る。色の数を数える（要調整）|

## 3. 合格の門

| 門 | 通る条件 | 通すのは |
|---|---|---|
| 構成 → 絵コンテ | 2.1 の機械の点検が全部通る＋作り手が構成を OK | 人 |
| 絵コンテ → 素材 | 設計表が埋まっている＋小さな下絵を作り手が選んだ | 人 |
| 段ごと（1大きな形 → … → 6仕上げ） | その段の点検が通る＋見る係の指摘が残っていない＋（一緒に／人が主導なら）作り手の OK | 度合いによる |
| 章 → 次の章 | 章を通しで見て作り手が OK（作り手：1章ずつ作って確かめる）| 人 |
| 本番の書き出し → 公開 | 2.7・2.8 が全部通る＋作り手が見た | **必ず人** |

- 門を通った物は固定する（AUTOMATION_DESIGN.md 2節）。あとから直すときは、固定を外す理由を残す。
- 「AI が主導」の工程でも、章の門と公開の門は人が通す。

## 4. 見直しのやり方

- **見る係は、作る所を見ていない別の AI**。渡すのは：出来た物（画像・動画）・その作業に当てはまる決まり・指摘帳・実物帳と手本帳の当てはまる所。作った理由は渡さない（引きずられないように）。
- 見る観点（作り手・2026-11-22〜23）：①ミスはないか ②自然に見えるか ③見ていて心地いいか（構図・デザインとして）④さらに良くするには。
- 「良くなったか」は前の版と並べて決める。並べずに「良くなった」と言わない。
- 作り手の新しい指摘は、必ず指摘帳に足す。同じ指摘を2度させない。
- 指摘が決まりに育ったら、段を決めて（部品／機械／読む）しまう。

## 5. 点検の道具（作る物）

| 道具 | 見る物 | 今ある土台 |
|---|---|---|
| 文書の検査 | 形の決まりどおりか・切れた参照・名前なし | なし（新しく作る）|
| 絵の点検 | 点の数・色の組・重なりの色・使い回し | `sozai_kimari.md` の決まり |
| 動きの点検 | 止まった時間・等速・同時の動き・語りとのずれ | `lint_shots.py` |
| 構図の点検 | 補助線・目を引く場所・つなぎ | `scene_measure.py`・`composition.md` |
| 書き出しの点検 | コマ・長さ・音量・黒い画面・下見との一致 | `final_export.py` の確かめ |
| 一覧の画像 | 段ごと・版ごとを1枚に並べる | `stage_sheet.py`・`review_sheets.py` |

点検の結果は、提案にも合格の門にも同じ形で付く：`{ check, 対象, 結果:'ok'|'warn'|'fail', 値, 基準, 見本 }`。

## 6. 質が上がったかを測る

道具ができても質が上がらなければ意味がない。次を続けて見る。

- 作り手が1場面に出す指摘の数（減っていくか）。
- 同じ指摘のくり返し（0 を目指す）。
- 1場面にかかる作り手の時間と、全体の時間。
- 公開後の数字（視聴維持率。とくに場面の切り替わりでの下がり方。作り手：「下がる所は大体、切り替わりの沈黙」）。
- 手本と並べた見比べ（節目ごとに、同じ題材の1場面を作って並べる）。
