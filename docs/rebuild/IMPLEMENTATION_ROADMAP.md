# 作る順番（IMPLEMENTATION_ROADMAP）

2026-11-27。**案**。まだ何も作り始めていない。期間は書かない（1人＋AI での速さは、最初の段階をやってみないと分からないため）。かわりに、段階ごとの「できたと言える条件」を書く。

## 進め方の決まり

1. **今の制作室を止めない**。別に建てて、できた所から移す。動画づくりは今の仕組みで続けられる。
2. **段階ごとに、本物の場面を1つ作る**。道具だけができて終わる段階を作らない。題材は進行中の「緑のアラビア」の序（母子のカバ）を通しの試し台にする。
3. **範囲の外は作らない**（PRODUCT_REQUIREMENTS.md 1節）。足したくなったら、先に「それが無いと今の場面が作れないか」を問う。
4. **段階の終わりに、作り手が続けるか・変えるか・やめるかを決める**。
5. 今ある実装ファイルは、移し終わるまで変えない・消さない。

## 段階の一覧

```
P  試作（決める材料を集める）
```

### P. 試作（作り始める前）
決めるための小さな実験。作った物は捨ててよい。

| 番号 | すること | 分かること |
|---|---|---|
| P0 | Claude に Illustrator／After Effects のスクリプトを書かせて1場面（作り手が AE を使える環境があれば）。無ければ、同じ場面を Rive か Cavalry で触ってみる | 自前で作る必要が本当にあるか |
| P1 | Canvas 2D で重い場面（部品200・ぼかし・合成・1080p）を動かして fps を測る。足りなければ CanvasKit でも | 描く方法 |
| P2 | 損のない書き出しと今の方式を、同じ場面で見比べ・時間を測る。60fps も | 書き出しの方法 |
| P3 | 命令・取り消し・小分けの保存の最小の形。2台で同時に直す | 保存と同期の方法 |
| P4 | 取っ手つきの曲線と図形の最小の描く画面で、作り手がクジラ級の部品を描いてみる | 作り手の手で質が出るか |

**できたと言える条件**：SYSTEM_ARCHITECTURE.md 3節の「おすすめ」が、実測と作り手の手ごたえで裏づけられるか、覆る。結果を同じ文書に書き足して、技術を決める。
**ここでやめる・変える場合**：P0 で既存の道具のほうが良いと分かったら、M1〜M3 の大半をやめ、「既存の道具＋自動化（M5）」に組み直す。

### M1. 核と描画
- 文書の形（素材・場面の最小）と検査。命令と取り消し。小分けの保存。
- 評価（文書＋時刻 → 描く物の一覧）と、Canvas に描く所。
- 今の部品のパックを新しい形に移す道具。
- **試し**：核は画面なしで動かして試す（命令を当てる → 取り消す → 元と同じ、を全部の命令で）。同じ文書から、ブラウザと作業場で同じ画像が出る（画素で比べる）。
- **できたと言える条件**：今の「母カバ」のパックを移して、新しい仕組みで同じ絵が出る。

### M2. 絵を描く（ベクターの画面）
- 図形（数値のまま）・点と取っ手・塗りと線・線の部品・重なりとグループ・付け根。
- 清書・なぞる下敷き・色の組・左右対称・形の合成。
- ひな形と写し。素材の棚。
- 今の parts.html の機能（フォルダ・Ctrl+C/V・塗りつぶし・ほかの画面から取る）を移す。
- **試し**：曲線・合成・当たり判定は数値で試す。画面は操作を自動で流して試す（今の Playwright のやり方）。
- **できたと言える条件**：作り手が、母子のカバと水辺の背景を、新しい画面だけで描き直し、「前より良い」と言う。素材の点検（点の数・色）が通る。
- M1 に依る。

### M3. リグと動き
- 親子と付け根で回す・差し替え・つまみ・名前つきの姿勢。
- キーフレーム・速度のグラフ・時間の線。入れ子（歩く・呼吸をくり返す部品）。
- 式と、動きの部品（揺れ・くり返し・遅れてついてくる・ばね・まばたき）。
- 次に：骨と IK。
- **試し**：同じ文書＋同じ時刻 → 同じ値（全部の種類の値で）。式は決まった入力に決まった答え。
- **できたと言える条件**：母カバが歩いて口を開け、子がついてくる動きを、作り手がグラフを触って直せる。動きの点検（止まった時間・等速）が通る。
- M2 に依る。

### M4. 場面・カメラ・語り
- 場面の木・奥行きとカメラ（動く・寄る・ついていく・手前のぼかし）・マスクと合成モード・場面のつなぎ。
- 語りの合図に鍵を結ぶ。声を作り直すと時刻が付け直される。
- 並べて増やす＋ばらつき（草・群れ）。
- 損のない書き出し。今の書き出しの流れ（声・字幕・音）から、新しい場面を呼ぶつなぎ。
- **試し**：語りを1文変えても、絵の合図がずれない。下見と本番のコマが一致。書き出した動画の点検。
- **できたと言える条件**：「緑のアラビア」の序（約1分）が、語り・字幕・音つきで書き出せ、作り手が今の版と並べて「良い」と言う。
- M3 に依る。

### M5. 自動化
- 工程ごとの度合いと許可。固定。
- 提案（前と後の見本つき）・採る／一部だけ採る／断る。作業ごとの取り消し・時点への巻き戻し。
- 作業係（会話・予約タスク）が、作業の札を読んで命令か提案を書き戻す。その作業に要る決まりだけを渡す。
- 見直しのサイクル（作る係・見る係・2案比べ）を仕組みに入れる。機械の点検を提案に付ける。
- **試し**：許可の外の命令が通らない（固定・削除・前の段）。提案を採る → 取り消す → 元どおり。AI が主導の途中で人が触ると、度合いが落ちる。
- **できたと言える条件**：同じ場面を、①人が主導 ②一緒に ③AI が主導 の3通りで、**同じ画面・同じデータのまま**切りかえながら作れる。AI のした変更を1つずつ見て、1つだけ戻せる。
- M3 に依る（M4 と並べて進められる）。最小の形（命令の記録と by の印）は M1 から入れておく。

### M6. 1本を通しで作る
- 新しい仕組みで、動画を1本、題材から公開まで作る。
- 足りない所を、その場で最小限だけ足す。
- 測る：作り手の時間・指摘の数・書き出しの時間・AI のトークン。
- **できたと言える条件**：公開できる1本ができる。作り手が「前の作り方より質が上で、続けられる」と言う。言えなければ、どこが足りないかを書いて M2〜M5 に戻る。

### M7. 移し替えと仕上げ
- 進行・候補・ポイント・運営・声・音を、新しい核の上に移す（要る物から）。今のページを1つずつ引退させる。
- 今の `data.json` を小分けの形へ。古い場面（JS で描いた物）は、そのまま見られる形で残す。
- スマホの確認・指摘の画面。通知。
- 残り：グラデーション・ぼかしの仕上げ、動きのぼけ、自動リグ、Lottie などの取りこみ・書き出し。

## 試しのやり方（全体）

- **核・ベクター・動き・評価**：画面なしで自動の試し。直すたびに全部流す。
- **描画**：決まった文書を描いて、前の結果の画像と比べる（変わったら知らせる）。
- **画面**：操作を自動で流す（押す・引く・貼る）。今の parts.html で使っているやり方。
- **同期**：2台分をまねて、同時に直す・古い画面から書く・時計がずれる、を流す（過去の事故を全部、試しにする）。
- **自動化**：許可の外の命令を全部試して、通らないことを確かめる。
- **人の目**：段階ごとに、一覧の画像1枚と短い動画を作り手に見せる。

## 危険（順番に関わるもの）

| P を飛ばして作り始め、あとで土台を変えることになる | P を必ず先に。結果を文書に残す |

| 作っている間、動画が出ない | 今の仕組みで動画づくりを続けてよい。ただし作り手の時間は1つなので、どちらに使うかを段階ごとに決める |
