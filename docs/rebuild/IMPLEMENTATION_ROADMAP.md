# 作る順番（IMPLEMENTATION_ROADMAP）

2026-11-27 改訂2。**案**。まだ何も作り始めていない。期間は書かない。かわりに、段階ごとの「できたと言える条件」を書く。

**改訂2で変えたこと**：①試作の順番を見直した ②P1 に下見と書き出しの画素の差の試しを入れた ③P3 に同期・重複・中断の試しを入れ、核の試し（P3a）と保存の試し（P3b）に分けた ④M1 の中身を、命令の核を先に固める形にした。

## 進め方の決まり

1. **最優先は最終の映像の質**。速さや自動化の割合のために、質を下げる近道を取らない。
2. **今の制作室を止めない**。別に建てて、できた所から移す。今ある実装ファイルは、移し終わるまで変えない・消さない。
3. **段階ごとに、本物の場面を1つ作る**。試し台は「緑のアラビア」の序（母子のカバ）。
4. **範囲の外は作らない**（PRODUCT_REQUIREMENTS.md 1節）。
5. **段階の終わりに、作り手が続けるか・変えるか・やめるかを決める**。
6. 試作で作った物は捨ててよい。試作の置き場は、今の実装と別のフォルダにする。

## 試作（作り始める前）

### 順番と理由

```
P0 既存の道具との比べ ──→ P4 曲線の画面で、質が出るか ──→ P3a 命令の核 ──→ P3b 保存と同期
   （道具が使えるなら最初）        （人の手が要る）          └→ P1 描く部品（一致と速さ）──→ P2 書き出し
```

提案された順番（P0 → P4 → P3 → P1 → P2）を、依りかかりと危険で確かめた。**結論：この順番でよい。変えるのは2点だけ。**

| 順 | 試作 | この位置にする理由 |
|---|---|---|
| 1 | **P0** | 結果しだいで、あとの試作の大半が要らなくなる。いちばん安く、いちばん大きく方向が変わる。**After Effects などを実際に触れる場合に限り最初**。触れないなら、半日の軽い形（下）にして先へ進む |
| 2 | **P4** | この計画の一番の問い「作り手の手で、質の高い部品が作れるか」に答える。答えが「無理」なら、命令の核も描く部品も作る意味が変わる。ほかの試作に依りかからない（捨ててよい最小の画面でよい）。**人の手と目が要る唯一の試作**なので、人の時間をここに先に使う |
| 3 | **P3a** | 命令の核は、このあと作る物すべての土台。P4 のあとにする理由：P4 で実際に行った操作の並び（点を足す・動かす・形を変える）が、核の試しの材料になる。「選んで取り消す」が実際の操作で使い物になるかは、本物の並びでないと分からない |
| 4 | **P3b** | 保存・同期・ぶつかり。P3a の命令と記録が要る |
| 5 | **P1** | 描く部品を決める。P3 とは依りかからない。P2 より前（書き出しは、選んだ描く部品で行う）|
| 6 | **P2** | P1 で選んだ部品で、損のない書き出し・60fps・時間を測る |

**変える2点**
1. **P3 を P3a（核）と P3b（保存と同期）に分ける。** 核は通信なしで試せ、結果がはっきり出る。保存のほうは GitHub の実際の動きに左右され、認証の決定（人の判断）も絡む。分けておけば、片方の遅れがもう片方を止めない。
2. **P1・P2 は、P3 と並べて進めてよい。** P1・P2 は測る作業が中心で、人の時間は「最後に見比べる」数分だけ。P3 とは依りかからない。順番を「P3 → P1 → P2」と書くのは、**決める順番**（土台を先に固める）としてで、作業を1列に並べる必要はない。

**提案の順番を変えなかった理由**：P1（描く部品）を P4 より前にする案も考えた。描く部品が変わるとふちの見え方が少し変わるため。けれども、P4 で確かめたいのは「形を作れるか」で、ふちの細かな差には左右されない。P1 を先にすると、人の要らない作業のために、一番大事な問いが後ろへ行く。だから P4 を先にする。

### 中身

**P0：既存の道具との比べ**
- 道具を触れる場合：Claude に Illustrator／After Effects のスクリプトを書かせて、母カバの1場面を作る。見る物：絵と動きの質・作り手の手間・人が途中で直せるか・AI の変更を1つだけ戻せるか・今の流れ（スマホ・チャット・GitHub）に乗るか。
- 触れない場合（軽い形）：無料で使える道具（Cavalry・Rive の無料の範囲）を半日触り、SYSTEM_ARCHITECTURE.md 6.1節の表を、実際に触った感想で書き直す。
- できたと言える条件：「自前で作る」を続けるか、「既存の道具＋自動化」に組み直すかを、作り手が決められる。

**P4：曲線の画面で、質が出るか**
- 最小の描く画面（捨ててよい）：点と取っ手・なめらか／角・図形（円・長丸・角丸）・塗りと線・重なり・なぞる下敷き・左右対称。
- 作り手が、手本の級の部品（クジラや母カバの頭）を、**自分の絵として**描く。
- 3通りで作って並べる：①人が描く ②AI が図形で下組みし、人が整える ③AI だけ。← どの度合いが質に効くかを、早いうちに見る。
- できたと言える条件：作り手が、並べた絵を見て「この道具なら質が出る」と言う。言えなければ、何が足りないか（道具か・腕か・手本の分析か）を書く。

**P3a：命令の核**（通信なし・画面なし）
- DATA_MODEL.md 9節の最小の形：部品・値・点・鍵の命令。形の検査・前提（版）・ひとまとめ・全体の決まり・記録。
- 試す：
  - 全部の種類で「当てる → 取り消す → 元と同じ」。
  - でたらめな並びを大量に当てても、全体の決まりが保たれる。同じ記録から同じ文書。
  - 同じ命令を2回当てても変わらない。途中で失敗する group は何も変えない。
  - **AI が A を変える → 人が A を直す → AI の分だけ戻す**：9.5節の表の全部の行。人の直しが残ることを確かめる。
  - P4 の実際の操作の並びを流し、「止まって聞く」が何回出るかを数える。
  - 許しの検査（度合い・許可・固定）が、送り主が誰でも効く。
  - 語りを直したときの、トークンの id の残り方と、宙に浮いた合図の出方（実際の語りの直しを使う）。
- できたと言える条件：上が全部通る。「止まって聞く」が、実際の操作で我慢できる回数に収まる。収まらなければ、命令の細かさを直す。

**P3b：保存と同期**
- 端末の中の送り箱・端末ごとの記録のファイル・GitHub への読み書き・読んだ記録を核に通す。
- 試す（2台分をまねて）：
  1. 同じ部品を2台で同時に直す（同じ値／別の値）。
  2. 別の部品を2台で同時に直す。
  3. 古い状態から保存しようとする。
  4. 同じ命令が重ねて送られる。
  5. 保存の途中で通信が切れる。
  6. 保存の途中でアプリが終わる。
  7. 端末の時計がずれている（過去の事故）。
  8. アプリ自体が古い版のまま開いている（過去の事故）。
  9. ファイルが 1MB を超える（過去の事故）。
- 見る物：どの場合も**何も失われない**・ぶつかりは見つかって残る・自動で入る物は入る・画面が何をすべきか（読み直す／選ぶ）が分かる。
- あわせて確かめる：何個かのファイルを一度に全部か無しかで書けるか／1時間あたりの回数の上限に当たらない送り方／「人の記録を、コミットの書き手で見分ける」ができるか／認証の案（SYSTEM_ARCHITECTURE.md 5節）のうち、作り手が選んだ物で動くか。
- できたと言える条件：1〜9 が全部、失わずに通る。

**P1：描く部品（一致と速さ）**
- 候補 R1（Canvas 2D）と R2（CanvasKit）で、同じ試しの場面を描く。
- **差の試し**：7つの場面（字／ふち／ぼかし／合成とマスク／グラデーション／画像／線）を、①作り手の端末の下見（Mac・Chromebook）②書き出しの環境 で描き、画素を比べる。
- 速さ：重い場面（部品200・ぼかし・合成・1080p）の fps。
- 絵の質：手本と並べて、ふち・ぼかし・色の帯を人の目で見る。
- できたと言える条件：描く部品が1つに決まる。決め手の順は ①一致 ②絵の質 ③速さ。差の試しが自動で流せる形で残る。

**P2：書き出し**
- P1 で決めた部品で、損のない途中経過 → 動画。今の方式（JPEG を挟む）と並べて見比べる。60fps。かかる時間。
- 「本番どおりに見る」の絵と、書き出した動画のコマが一致するか。
- できたと言える条件：書き出しの流れが決まり、今の方式との差（質・時間）が数字と見比べで分かる。

**試作のあと**：結果を SYSTEM_ARCHITECTURE.md に書き足し、技術を決める。ここで初めて、作る段階（M1〜）に入る。

## 作る段階

```
M1 核と描画 ─→ M2 絵を描く ─→ M3 リグと動き ─→ M4 場面・カメラ・語り
                                   └──→ M5 自動化 ←──┘
                                            └→ M6 1本を通しで ─→ M7 移し替えと仕上げ
```

### M1. 核と描画
- 命令の核を、試作から本番の形へ（型・検査・前提・ひとまとめ・記録・取り消し・選んで取り消す・許しの検査）。保存と同期。
- 評価（文書＋時刻 → 描く物の一覧）と、決めた描く部品。「本番どおりに見る」。
- 今の部品のパックを新しい形に移す道具。
- 試し：P3a・P3b・P1 の試しを、毎回流す自動の試しにする。
- できたと言える条件：今の「母カバ」を移して、新しい仕組みで同じ絵が出る。下見と書き出しの差の試しが通る。

### M2. 絵を描く
- 図形・点と取っ手・塗りと線・線の部品・重なりとグループ・付け根。清書・なぞる下敷き・色の組・左右対称・形の合成。ひな形と写し。素材の棚。
- できたと言える条件：作り手が、母子のカバと水辺を新しい画面だけで描き直し、「前より良い」と言う。必須の点検が通る。

### M3. リグと動き
- 親子と付け根・差し替え・つまみ・姿勢。鍵・速度のグラフ・時間の線。入れ子。式（小さな専用の言葉）と動きの部品。次に骨と IK。
- 試し：同じ文書＋同じ時刻 → 同じ値。式の上限と輪の検査。
- できたと言える条件：母カバが歩いて口を開け、子がついてくる動きを、作り手がグラフを触って直せる。

### M4. 場面・カメラ・語り
- 場面の木・奥行きとカメラ・マスクと合成・つなぎ。語りのトークンに鍵を結ぶ。並べて増やす＋ばらつき。書き出し。今の流れ（声・字幕・音）とのつなぎ。
- 試し：語りを1文変えても合図がずれない・消えた言葉の合図は宙に浮いて知らされる。
- できたと言える条件：「緑のアラビア」の序が、語り・字幕・音つきで書き出せ、作り手が今の版と並べて「良い」と言う。

### M5. 自動化
- 度合い・許可・固定の画面。提案（前と後の見本・依りかかっている物）・採る／一部だけ採る／断る。AI の変更だけを戻す画面。作業係。見直しのサイクル。点検の3つの重さと意図の札。
- 試し：許しの外の命令が通らない。関係のない所を直しても提案が無効にならない。提案が触る値を直すと、その命令だけ無効になる。
- できたと言える条件：同じ場面を、Human・Collaborative・AI の3通りで、**同じ画面・同じデータのまま、途中で切りかえながら**作れる。AI のした変更を1つだけ戻しても、人の直しが残る。
- M3 に依る（M4 と並べて進められる）。命令の核の側（許しの検査・記録）は M1 で入っている。

### M6. 1本を通しで作る
- 新しい仕組みで、動画を1本、題材から公開まで。測る：作り手の時間・指摘の数・意図の札の数・書き出しの時間・AI のトークン。
- できたと言える条件：公開できる1本ができ、作り手が「前の作り方より質が上で、続けられる」と言う。

### M7. 移し替えと仕上げ
- 進行・候補・ポイント・運営・声・音を、新しい核の上へ。今のページを1つずつ引退。スマホの確認・指摘。通知。残りの表現（グラデーション・ぼかしの仕上げ・動きのぼけ・自動リグ・ほかの形式の取りこみ）。
