## 進め方の決まり

1. **最優先は最終の映像の質**。速さや自動化の割合のために、質を下げる近道を取らない。
2. **今の制作室を止めない**。別に建てて、できた所から移す。今ある実装ファイルは、移し終わるまで変えない・消さない。
3. **段階ごとに、本物の場面を1つ作る**。試し台は「緑のアラビア」の序（母子のカバ）。
4. **範囲の外は作らない**（PRODUCT_REQUIREMENTS.md 1節）。
5. **段階の終わりに、作り手が続けるか・変えるか・やめるかを決める**。
6. 試作で作った物は捨ててよい。試作の置き場は、今の実装と別のフォルダにする。
7. **自前で完結させる。ただし、それ自体を目的にしない。** 目的は質。外部ライブラリや描くエンジンは使ってよい（SYSTEM_ARCHITECTURE.md 6.1節の条件で）。既存の有料の制作ソフトを、工程の中核に置かない。

### 中身

**P4：曲線の画面で、質が出るか**
- 最小の描く画面（捨ててよい）：点と取っ手・なめらか／角・図形（円・長丸・角丸）・塗りと線・重なり・なぞる下敷き・左右対称。
- 作り手が、手本の級の部品（クジラや母カバの頭）を、**自分の絵として**描く。
- 3通りで作って並べる：①人が描く ②AI が図形で下組みし、人が整える ③AI だけ。← どの度合いが質に効くかを早く見る。
- 外部ライブラリの評価：形の合成（足す・くり抜く）や曲線の計算に、既存のライブラリを使うか自前で書くかを、ここで当たりを付ける。
- 行った操作の並び（点を足す・動かす・形を変える）を記録し、P3a に渡す。
- **できたと言える条件**（P0 を省いたぶん厳しくする）：
  1. 作り手が、3通りを並べた絵を見て「この道具なら質が出る」と言う。
  2. 手本と並べて、輪郭のなめらかさ・形の洗練で見劣りしない部品が、少なくとも1つできる。
  3. 言えない・できない場合は、何が足りないかを分けて書く（道具の機能／作り手の慣れ／AI の下組み／手本の分析）。**「既存のソフトを使う」は答えにしない**。足りない物を足す道（外部ライブラリを含む）を探す。

**P3a：命令の核**（通信なし・画面なし）
- DATA_MODEL.md 9節の最小の形：部品・値・点・鍵の命令。形の検査・前提（版）・ひとまとめ・全体の決まり・記録。
- 試す：
  - 全部の種類で「当てる → 取り消す → 元と同じ」。
  - でたらめな並びを大量に当てても、全体の決まりが保たれる。同じ記録から同じ文書。
  - 同じ命令を2回当てても変わらない。途中で失敗する group は何も変えない。
  - **AI が A を変える → 人が A を直す → AI の分だけ戻す**：9.5節の表の全部の行。人の直しが残ることを確かめる。
  - P4 の実際の操作の並びを流し、「止まって聞く」が何回出るかを数える（P4 から届いたら）。
  - 許しの検査（度合い・許可・固定）が、送り主が何と名乗っても効く。
  - 語りを直したときの、トークンの id の残り方と、宙に浮いた合図の出方。
- できたと言える条件：上が全部通る。「止まって聞く」が、実際の操作で我慢できる回数に収まる。

**P3b：保存と同期**
- 前半（まねた GitHub で）：端末の中の送り箱・端末ごとの記録のファイル・順番の決め方・読んだ記録を核に通す。
- 後半（本物の GitHub で）：同じ試しを、実際の API で。
- 試す（2台分をまねて）：
  1. 同じ部品を2台で同時に直す（同じ値／別の値）。
  2. 別の部品を2台で同時に直す。
  3. 片方がオフラインの間に、もう片方が直す。
  4. オフラインだった端末が、つなぎ直して古い命令を送る。
  5. 命令の順番が入れかわって届く。
  6. 古い状態から保存しようとする。
  7. 同じ命令が重ねて送られる。
  8. 保存の途中で通信が切れる。
  9. 保存の途中でアプリが終わる。
  10. 端末の時計がずれている（過去の事故）。
  11. アプリ自体が古い版のまま開いている（過去の事故）。
  12. ファイルが 1MB を超える（過去の事故）。
- 見る物：どの場合も**何も失われない**・すでに見えていた結果が、あとから書きかわらない・ぶつかりは見つかって残る・画面が何をすべきか（読み直す／選ぶ）が分かる。
- あわせて確かめる：1時間あたりの回数の上限に当たらない送り方／送り主を確かめる方法（SYSTEM_ARCHITECTURE.md 5b節）が実際に動くか。
- **始める前に要る判断**：順番の決め方（5b節の「順番の台帳」）と、送り主の確かめ方（端末の署名）でよいか。試作の間はトークンを今のまま使ってよいか。
- できたと言える条件：1〜12 が全部、失わずに通る。

**P1：描く部品（速さと一致）**
- 候補 R1（Canvas 2D）と R2（CanvasKit）で、同じ試しの場面を描く。CanvasKit は外部の配信元から読みこまず、自分の所に置いて使う。
- **差の試し**：7つの場面（字／ふち／ぼかし／合成とマスク／グラデーション／画像／線）を、①作り手の端末の下見（Mac・Chromebook）②書き出しの環境 で描き、画素を比べる。
- 速さ：重い場面（部品200・ぼかし・合成・1080p）の fps。
- 絵の質：手本と並べて、ふち・ぼかし・色の帯を人の目で見る。
- 外部ライブラリの評価：CanvasKit の大きさ・読みこみの時間・使用の条件・保守の続き方。
- できたと言える条件：描く部品が1つに決まる。決め手の順は ①一致 ②絵の質 ③速さ。差の試しが自動で流せる形で残る。

**P2：書き出しの質**
- 流れづくり（P1 と並べて）：コマを1枚ずつ取り出す → 損のない途中経過 → 動画。今の方式（JPEG を挟む）と並べる道具。
- 測り（P1 のあと）：決めた描く部品で、見比べ・60fps・かかる時間。「本番どおりに見る」の絵と、書き出した動画のコマが一致するか。
- 外部ライブラリの評価：動画に包む部品（ffmpeg を続けて使うか、ブラウザの中で完結させるか）。
- できたと言える条件：書き出しの流れが決まり、今の方式との差（質・時間）が数字と見比べで分かる。

**試作のあと**：結果を SYSTEM_ARCHITECTURE.md に書き足し、技術を決める。ここで初めて、作る段階（M1〜）に入る。

## 作る段階

```
M1 核と描画 ─→ M2 絵を描く ─→ M3 リグと動き ─→ M4 場面・カメラ・語り
                                   └──→ M5 自動化 ←──┘
                                            └→ M6 1本を通しで ─→ M7 移し替えと仕上げ
```

### M1. 核と描画
- 命令の核を、試作から本番の形へ（型・検査・前提・ひとまとめ・記録・取り消し・選んで取り消す・許しの検査）。保存と同期。
- 評価（文書＋時刻 → 描く物の一覧）と、決めた描く部品。「本番どおりに見る」。
- 今の部品のパックを新しい形に移す道具。
- 試し：P3a・P3b・P1 の試しを、毎回流す自動の試しにする。
- できたと言える条件：今の「母カバ」を移して、新しい仕組みで同じ絵が出る。下見と書き出しの差の試しが通る。

### M2. 絵を描く
- 図形・点と取っ手・塗りと線・線の部品・重なりとグループ・付け根。清書・なぞる下敷き・色の組・左右対称・形の合成。ひな形と写し。素材の棚。
- できたと言える条件：作り手が、母子のカバと水辺を新しい画面だけで描き直し、「前より良い」と言う。**手本と並べた見比べ**（同じ題材の1場面）を行い、足りない所を書き出す。必須の点検が通る。

### M3. リグと動き
- 親子と付け根・差し替え・つまみ・姿勢。鍵・速度のグラフ・時間の線。入れ子。式（小さな専用の言葉）と動きの部品。次に骨と IK。
- 試し：同じ文書＋同じ時刻 → 同じ値。式の上限と輪の検査。
- できたと言える条件：母カバが歩いて口を開け、子がついてくる動きを、作り手がグラフを触って直せる。

### M4. 場面・カメラ・語り
- 場面の木・奥行きとカメラ・マスクと合成・つなぎ。語りのトークンに鍵を結ぶ。並べて増やす＋ばらつき。書き出し。今の流れ（声・字幕・音）とのつなぎ。
- 試し：語りを1文変えても合図がずれない・消えた言葉の合図は宙に浮いて知らされる。
- できたと言える条件：「緑のアラビア」の序が、語り・字幕・音つきで書き出せ、作り手が今の版と並べて「良い」と言う。

### M5. 自動化
- 度合い・許可・固定の画面。提案（前と後の見本・依りかかっている物）・採る／一部だけ採る／断る。AI の変更だけを戻す画面。作業係。見直しのサイクル。点検の3つの重さと意図の札。
- 試し：許しの外の命令が通らない。関係のない所を直しても提案が無効にならない。提案が触る値を直すと、その命令だけ無効になる。
- できたと言える条件：同じ場面を、Human・Collaborative・AI の3通りで、**同じ画面・同じデータのまま、途中で切りかえながら**作れる。AI のした変更を1つだけ戻しても、人の直しが残る。
- M3 に依る（M4 と並べて進められる）。命令の核の側（許しの検査・記録）は M1 で入っている。

### M6. 1本を通しで作る
- 新しい仕組みで、動画を1本、題材から公開まで。測る：作り手の時間・指摘の数・意図の札の数・書き出しの時間・AI のトークン。
- できたと言える条件：公開できる1本ができ、作り手が「前の作り方より質が上で、続けられる」と言う。

### M7. 移し替えと仕上げ
- 進行・候補・ポイント・運営・声・音を、新しい核の上へ。今のページを1つずつ引退。スマホの確認・指摘。通知。残りの表現（グラデーション・ぼかしの仕上げ・動きのぼけ・自動リグ・ほかの形式の取りこみ）。

## 最初の一歩
1. **P4 を始める**（作り手の手が要る）。置き場は、今のリポジトリの中の独立したフォルダ。今ある実装ファイルには触らない。
2. 並べて、P3a と P1（と P2 の流れづくり）を進める（作り手の手は要らない）。
3. P3b の後半までに、作り手が決める：順番の決め方・送り主の確かめ方・試作の間のトークンの扱い（SYSTEM_ARCHITECTURE.md 5b節）。
