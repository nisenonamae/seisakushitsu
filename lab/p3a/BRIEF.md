# P3a の指示書（命令の核＝Command Engine）

担当は1人。ほかに P4・P1 を別の担当が同時に進めている。**触ってよいのは `lab/p3a/` の中だけ。**

## まず読む物（設計。これが仕様）
- `lab/README.md`
- `docs/rebuild/DATA_MODEL.md`（とくに 1・3・4・6・8・9節）
- `docs/rebuild/SYSTEM_ARCHITECTURE.md` の 3節（命令の核の約束）と 5b節（順番・送り主の追加検討）
- `docs/rebuild/AUTOMATION_DESIGN.md` の 1〜6節（度合い・許可・固定・提案）
- `docs/rebuild/IMPLEMENTATION_ROADMAP.md` の「P3a」

## 目的
文書を変えるただ1つの道である「命令の核」が成り立つかを確かめる。**画面にも GitHub にも通信にも依らない、単独で動く部品**として作り、試せる状態にする。とくに大事なのは：**AI の変更だけを、あとから選んで取り消せること。AI が部品 A を変え、そのあと人が同じ A を直していても、AI の分だけを戻して、人の直しが壊れないこと。**

## 作る物（Node 22。依存なしが望ましい＝素の ES modules＋`node:test`。型は JSDoc でよい）
1. **文書の最小の形**：場面・部品（group / shape / line）・値（`Value`＝static / keys / expr / ref の札つき）・形の点（id・位置・取っ手・角）・鍵（id つき）・親子と順番・部品ごとの版（rev）・表紙（度合い・許可・固定）
2. **命令**（DATA_MODEL 9.2節の一覧から、少なくとも）：`node.add` `node.remove` `node.move` `node.rename`／`prop.set` `prop.nudge` `prop.kind`／`pt.add` `pt.remove` `pt.nudge` `pt.handle` `pt.corner`／`key.add` `key.remove` `key.retime` `key.value`／`mode.set` `perms.set` `lock.add` `lock.remove`／`revert`。種類ごとに引数の形と版（`v`）を持ち、当てる前に検査する。古い版の命令を新しい形に移す例を1つ入れる
3. **当てる手順**（9.3節の①〜⑦）：重複（同じ id は1回だけ）→ 形の検査 → 許しの検査 → 前提（base の rev）→ 控えの上で当てる（group は全部か無しか）→ 全体の決まり（切れた参照・親子の輪・ref の輪）→ 記録。断るときは理由の札（`duplicate` `invalid` `forbidden` `locked` `stale` `conflict` `breaks-invariant`）
   - 取り消しに要る情報（効果：set / delta / insert / remove / move）は、**核が当てる時に自分で作る**。送る側が書いた物は信じない
   - 核は「文書＋命令 →（新しい文書＋記録）か（断り＋理由）」を返す計算。時計・乱数・通信・画面に触らない
4. **許しの検査**：度合い（human / collab / ai）・許可・固定（frozen / ask）を核が強制する（AUTOMATION_DESIGN 3節）。collab のとき AI の命令は「提案に回す」という結果を返す。**送り主が人か AI かは、命令の中の名乗りではなく、呼び出す側が渡す「確かめられた身元」で決める**（5b節。署名そのものは作らなくてよい。名乗りを偽っても権限が増えないことを試す）
5. **ふつうの取り消し**と、**選んで取り消す（9.5節）**：戻したい記録の効果を1つずつ見て、その後に何が起きたかで「戻した／上書き済みなので何もしない／止まって聞く」に分ける。9.5節の表の**全部の行**を実装し、結果を一覧で返す。止まって聞く場合は、何が一緒に消えるかを返す。人の直しを黙って壊さない
6. **記録からの作り直し（replay）**：同じ記録からは同じ文書。記録を読むときも検査を通し、通らない命令は当てない
7. （余力があれば）提案と、提案が生きているかの判定（9.7節 `reads`）／語りのトークンと合図（6節）／式の小さな言葉の、参照の輪と上限の検査

## 試し（`node --test` で全部流せること）
- 全部の種類の命令で「当てる → 取り消す → 元と同じ」
- 種を決めた乱数で、でたらめな命令の並びを大量に（数千〜数万）当て、いつでも全体の決まりが保たれること・同じ記録から同じ文書になること
- 同じ命令を2回当てても変わらない。途中で失敗する group は何も変えない
- **AI が A を変える → 人が A を直す → AI の分だけ戻す**：効果の種類の全部の組（9.5節の表の全行）で、人の直しが残ること
- 許しの外の命令は、名乗りを偽っても通らない
- **「止まって聞く」がどのくらい出るかを測る**：絵を描く作業らしい操作の並び（AI が下組みを作る → 人が点を動かす・色を変える・部品を足す・並べかえる…）を何通りか作り、AI の作業を選んで戻したときに、戻した／上書き済み／聞く が何件かを数える。`traces/` に、あとで P4 の本物の操作の記録（JSON）を入れて流せる入口を用意する（P4 の記録の形はまだ決まっていないので、読みこむ変換を1か所にまとめる）

## 記録
- `RESULTS.md`：①成果物（ファイルと入口の関数）②確かめた結果（試しの数・乱数の試しの回数・9.5節の表の行ごとの結果・「止まって聞く」の割合）③まだ解けていないこと（設計で足りなかった所・迷った所・決め打ちにした所）④**設計書をこう直すべき、という提案**（設計書そのものは変えない）⑤本番に採る前に評価が要ること
- `README.md`：試しの流し方

## 決まり
- `lab/p3a/` の外は変えない（設計書も）。認証トークン・GitHub の API・外部のスクリプトに触らない。`node_modules` はコミットしない
- 文書・記録・コードの中の説明は日本語でよい（識別子は英語）

## 終わり方
