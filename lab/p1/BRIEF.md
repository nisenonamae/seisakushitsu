# P1 の指示書（描く部品の技術の比べ）

担当は1人。ほかに P4・P3a を別の担当が同時に進めている。**触ってよいのは `lab/p1/` の中だけ。**

## まず読む物
- `lab/README.md`
- `docs/rebuild/SYSTEM_ARCHITECTURE.md` の 4節（下見と書き出しを同じ絵にする。候補 R1＝Canvas 2D、R2＝CanvasKit）と 6.1節（外部ライブラリを使うときの条件）
- `docs/rebuild/IMPLEMENTATION_ROADMAP.md` の「P1」「P2」
- `docs/rebuild/QUALITY_STANDARDS.md` の 3.8節
- 参考：今の書き出し `tools/vis/parts3.py`（1コマごとに JPEG にして取り出している）。**読むだけ・変えない**

## 目的
新しい仕組みの「描く部品」を1つに決めるための材料を出す。決め手の順番は **①下見と書き出しの一致 ②絵の質 ③速さ**。最優先は最終の映像の質。絵柄は kurzgesagt のようなベクター（平らな色・なめらかな輪郭・太さ一定の線・控えめなぼかしとグラデーション・重ね）。

## 作る物
1. **小さな「描く物の一覧」の形**（ベジェの道・塗り・線〔太さ・端・角〕・グラデーション・ぼかし・合成モード・マスク・画像・字・変形・透明度）と、それを描く **2つの描く部品**：
   - R1：Canvas 2D
   - R2：CanvasKit（npm の `canvaskit-wasm` を取ってきて、**`vendor/` に置いて使う。外の配信元から読みこまない**。版・大きさ・使用の条件を記録）。GPU（WebGL）で描く設定と、CPU で描く設定の両方
   - ほかに有力な候補があれば、候補と使用の条件を調べて記録（全部を実装しなくてよい）
2. **試しの場面**（同じ一覧を両方で描く。1920×1080）
   - 一致を見る7つ：①字（日本語を含む。字は `fonts/` に置いた物だけ。使用の条件を確かめて記録。大きすぎる字のファイルはコミットしない）②ふち（細い形・斜めの線・小さな円）③ぼかし ④合成とマスク（乗算・スクリーン・加算・切り抜き）⑤グラデーション（色の帯が出やすい、ゆるい変化を含む）⑥画像の拡大縮小 ⑦線（細い・太い・端・角・曲線）
   - 絵の質を見る1つ：kurzgesagt 風の小さな場面（空のグラデーション・丸い形の重なり・光の線・控えめなぼかし）。他人の絵を写さず、自分で組む
   - 速さを見る1つ：重い場面（部品 200・ぼかし・合成・動く）
3. **測る・比べる道具**
   - 画素の差を測る道具（2枚 → 違う画素の割合・いちばん大きい色の差・差を強調した画像）
   - **書き出しの側**：裏で動かすブラウザ（Python の playwright。Chromium あり）で、各場面を R1・R2（GPU／CPU）で描いて PNG に。同じ物を2回描いて毎回同じになるかも見る。起動の設定（GPU を切る・ソフトウェアで描く、など）を変えて、環境が違うときの差の当たりを付ける
   - **下見の側（作り手の端末で開くページ）`index.html`**：全部の場面を R1・R2 で描いて見せ、fps を測り、結果（各場面の PNG と、端末・ブラウザの情報・fps）を**1つのファイルとして書き出せる**。作り手は Mac と Chromebook で開き、そのファイルをチャットに添付して返す。届いたファイルと書き出しの側を比べる命令を用意する（例：`python3 lab/p1/compare.py <届いたファイル>`）
   - 速さ：重い場面の 1コマあたりの時間（描く・画素を取り出す）。P2 の下ごしらえとして、コマを取り出す方法（PNG／生の画素）の時間も
4. **結果の一覧の画像**（数枚にまとめる）：場面ごとに R1・R2 を並べた物、ふち・ぼかし・グラデーションを拡大した物、差を強調した物。自分の目で見て、気づいたことを書く
5. **記録 `RESULTS.md`**：①成果物 ②確かめた結果（場面ごとの差の数字・fps・1コマの時間・毎回同じになったか・CanvasKit の大きさと読みこみの時間）③**確かめられなかったこと**（この作業場は1台なので、端末をまたいだ一致は、作り手の結果が届くまで分からない。「未確認」と書く）④いまの時点でのおすすめと、その確からしさ ⑤外部ライブラリの評価（6.1節の条件に照らす）⑥本番に採る前に評価が要ること。`使い方.md` に、作り手が Mac／Chromebook でページを開いて結果のファイルを送るまでを、どこを押すか1つずつ

## 決まり
- `lab/p1/` の外は変えない。**`localStorage` の `gh_` で始まる項目に触らない。GitHub の API を呼ばない。外部のスクリプト・字・画像を実行時に読みこまない**（ページは GitHub Pages の `…/seisakushitsu/lab/p1/` でも、手元のサーバーでも動くこと）
- 画面の言葉は日本語
- `node_modules` はコミットしない。`vendor/` に置くのは要るファイルだけ。結果の画像は、まとめた一覧の物だけをコミットする（全部で数MB まで）
- 数字は、測った物だけを書く。測っていない物・1台でしか見ていない物は、そう書く

## 終わり方
最後の報告（日本語・短く）：作ったファイル／測った結果（場面ごとの差・速さ）／絵の質で気づいたこと／確かめられなかったこと／いまのおすすめと確からしさ／作り手にしてもらうこと／push できたか（コミットの番号）。
