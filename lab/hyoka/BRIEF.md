# 人の目での評価の画面（lab/hyoka）の指示書（2026-11-29）

担当は1人。**触ってよいのは `lab/hyoka/` の中だけ。** 制作室の実装・`lab/` のほかのフォルダ（p4・p1・p3a・p3r・e2〜e6）・設計書は変えない（読むのはよい。絵のデータ・描き方・動きの道具は `lab/hyoka/` に写して使う。写した元を記録する）。`PLAN.md`（先に決めた計画）は**変えない**。ほかの担当・評価者は立てない。本番に採る物は作らない。

## まず読む物
`lab/README.md`（とくに：`localStorage` の `gh_` で始まる項目に触らない・GitHub の API を呼ばない・外部のスクリプト／字／画像を実行時に読みこまない・自分の接頭辞を使う）／`lab/hyoka/PLAN.md`（見せる版・項目・組・読み方。**このとおりに作る**）／`lab/p4/使い方.md`・`lab/p4/compare.js`（P4 の「評価.json」の形。P4 は変えない）／`lab/e5/RESULTS.md`・`lab/e5/motions.json`・`lab/e5/out/eval/対応.json`／`lab/e6/out/versions.json`。

## 作る物：作り手が Mac（と Chromebook）で開いて、1人で評価する1ページ
`lab/hyoka/index.html`（JS・CSS・データは同じフォルダに。素の HTML/JS。外部のスクリプトなし・通信は自分のフォルダの中だけ）。GitHub Pages（`…/seisakushitsu/lab/hyoka/`）で動くこと。

1. **見せる絵**（PLAN.md の表のとおり）
   - E5 の A・D・E・F と P4 の AI のみ：止まった絵＋**動き（歩く・首を振る）**。動きは、コマを描いて並べた物を、ページの中でくり返し再生する（止める・コマ送り・速さを変える、ができる。再生は 12〜24 コマ/秒。E5 の `motions.json` のコマのあいだを補って、なめらかにしてよい。補い方を記録）。部品を付け根で回して描く道具は `lab/e5/tools/` を写して使い、**あらかじめ画像にして置く**（ページの中で絵を計算し直さない。作り手の端末で同じ絵になるように）。
   - E6 の 10 版：止まった絵。脚の版（脚を短く・長く・柱・ゾウ足・丸いもも・ひざと足首）と基準は、E5 と同じ歩きの動きを当てられるなら当てて、動きも付ける。当てられない版は「止まった絵だけ」とし、理由を記録（むりに作らない）。
   - P4 の「人のみ」「AI の下組み＋人」：**作り手が P4 で書き出した「評価.json」（または P4 の絵の JSON）を、このページでファイルとして選んで読みこむ**と出る。読みこむまでは、その枠は出さず、「P4 で描いた絵を読みこむと、比べる組が2つ増えます」と案内する。P4 の絵は `lab/p4/geom.js` を写した描き方で描く（止まった絵だけ）。P4 の保存（`localStorage` の `lab:p4:`）を**直接は読まない**（P4 の側を変えず、ファイルで渡す形だけにする）。
   - 絵には、版の名前・作り方が分かる字を入れない。背景・大きさをそろえる。拡大して見られる。
2. **評価の流れ**（PLAN.md のとおり）
   - 第1部：1つずつ見て、項目ごとに 1〜5 と、ひとこと（任意）。「これで動画に出せる」はい／いいえ。動きがある物は、止まった絵と動きを切りかえて見られる。
   - 第2部：2つを並べて、項目ごとに「左・右・差なし」と、ひとこと（任意）。動きの組は、2つを同時に再生する。組は左右を入れかえて2回、あいだに別の組をはさむ。
   - **番号と順番は乱数**（種を最初に決め、結果に残す）。同じ絵のくり返し（PLAN.md）を、知らせずに混ぜる。作り方・版の名前・仮説は、評価が終わって書き出すまで、画面のどこにも出さない（ページの元を読めば分かるのはしかたがない。対応表は、名前が読み取りにくい形で持つ必要はないが、画面には出さない）。
   - 途中で閉じても続きから（`localStorage` の `lab:hyoka:` で始まる名前だけを使う）。進み具合（あと何個）を出す。戻って直せる。全部で 30〜40 分に収まる数にする（PLAN.md の版と組のとおりなら、その見こみ。多すぎると感じたら、**減らさずに**、そう記録する）。
   - 画面の言葉は日本語。どこを押すかが分かる言葉で。ボタンを押してもスクロール位置が戻らないこと。点はキーボード（1〜5）でも入れられる。
3. **結果の書き出し**：「評価を書き出す」で JSON 1つ（`人の評価_<日付>.json`）。中身：評価した人＝人（`"rater":"human"`）と分かる印／乱数の種／出した順／番号と版の対応／項目ごとの点・選び・ひとこと／「動画に出せる」の答え／1つにかけた時間／端末とブラウザ／読みこんだ P4 の絵（あれば、そのデータも）／このページの版。**AI の評価者の結果は入れない**（別の物として分ける）。書き出したあとで、番号と版の対応を画面で見られる。
4. **読むための道具** `lab/hyoka/tools/yomu.py`：届いた JSON を読み、PLAN.md の「読み方の決まり」のとおりに表にする（ぶれ／差がある・決まらない／AI の評価者と合ったか／プロ級に届いたか）。決まりは PLAN.md のまま実装し、変えない。AI の評価者の結果は、PLAN.md の表を写して持つ。作り物の答えで動くことを試す。
5. `使い方.md`：Mac で、どこを開いて、どこを押すかを1つずつ。P4 の絵を読みこむ手順。終わったら JSON をチャットに添付する所まで。`RESULTS.md`：①作ったファイル ②見せる版と、その元（どのフォルダの、どのファイル）③動きの作り方 ④自分で確かめたこと（裏で動かすブラウザで、最初から最後まで通す。JS のエラー 0・外への通信 0・途中で閉じて続きから・書き出した JSON を `yomu.py` で読める）⑤確かめられなかったこと（Mac の実機・Safari・トラックパッド、など）⑥限界。

## 道具と git
裏で動かすブラウザは Python の playwright（Chromium あり）。サーバーはポート 8811。一時ファイルは `/tmp/hyoka/`。画像は、動きのコマを含めて全部で 15MB まで（幅 800 ほど・JPEG か WebP でよい。コマの数と大きさで調整し、決めた値を記録）。区切りごとに手元でコミットする（利用の上限で止まっても残るように）。
