# P4 の指示書（曲線の画面で、質が出るか）

担当は1人。ほかに P3a・P1 を別の担当が同時に進めている。**触ってよいのは `lab/p4/` の中だけ。**

## まず読む物
- `lab/README.md`（全部の試作で守ること。必ず守る）
- `docs/rebuild/IMPLEMENTATION_ROADMAP.md` の「P4」
- `docs/rebuild/DATA_MODEL.md` の 4節（絵の形。点は id・位置・取っ手 in/out・角 を持つ）
- `docs/refs/sozai_kimari.md`（素材の決まり）
- `parts.html`（今ある「部品で直す」。**読むだけ・変えない**。`HND`（取っ手を自動で決める式）・`fitPts`（清書）・なぞる画像の作りを参考にしてよい。コードを lab/p4 に写して使ってよい）

## 目的
作り手（1人の制作者。Mac のマウス／トラックパッドで操作する）が、**自分の手で、kurzgesagt 級に洗練されたベクターの部品を作れるか**を確かめる。前の道具（ひと筆で囲む・点が多い）では「マウスでは無理」と言われた。作り手の観察：kurzgesagt の動物は、部品の数は多くないが一つ一つが図形的で洗練されている。少ない点・長いなめらかな曲線・1部品1色・光や口は太さ一定で端の丸い線。

そして、**同じ題材・同じ品質の目標**で、次の3つの作り方を比べられるようにする：
1. **人のみ**：作り手が空の画面から描く
2. **AI の下組み＋人**：AI（＝担当のあなた）が図形で下組みした物を、作り手が直す
3. **AI のみ**：AI（＝あなた）が仕上げまでやった物

## 作る物（素の HTML/JS。外部のスクリプトなし・通信なし）
1. **描く画面 `index.html`**（JS・CSS は同じフォルダに分けてよい）。最低限：
   - **ペン**：押す＝角の点、押して引く＝なめらかな点（取っ手が出る）。始点を押すと閉じる。開いたままの線も作れる
   - **点を直す**：点を動かす／取っ手を動かす（両側そろえる・片側だけ）／なめらか⇔角の切りかえ／線の上を押して点を足す／点を消す／取っ手を自動に戻す（`HND` の式）
   - **図形**：円・だ円、角丸の四角（丸みを変えられる）、長丸。数値のまま持ち、あとで「自由な形に変える」ができる
   - **塗りと線**：塗りの色／線の色・太さ・端の丸さ。**線だけの部品**（開いた曲線＋太さ。光・口・すじ用）
   - **部品の一覧**：重なり順・名前・見せる／隠す・固定・グループ。複数選び
   - **動かす・回す・大きさ**（選んだ部品。複数も）。複製（Cmd+C / Cmd+V、Cmd+D）
   - **左右対称**（少なくとも「左右反転の写しを作る」は必須）
   - **なぞる下敷き**（画像ファイルを選ぶ／貼り付ける。濃さ・位置・大きさ。保存にも書き出しにも入れない）
   - **清書**（点を減らしてなめらかに）
   - 取り消し・やり直し（Cmd+Z / Shift+Cmd+Z）。拡大縮小・画面の移動（トラックパッドの2本指・ピンチ、マウスのホイール、スペース＋引く）
   - 色の組（題材ごとに決まった色。そこから選ぶ。自由な色も可）
   - 保存：端末の中（`localStorage` の `lab:p4:` で始まる名前）＋ **ファイルに書き出す／読みこむ（JSON）**＋ PNG の書き出し
   - **操作の記録**：行った操作（種類・相手の id・引数・時刻）をためて、JSON で書き出せる（P3a の試しの材料）。作業していた正味の時間も測る
2. **題材と目標 `GOAL.md`** と、画面の中の「目標」表示。題材は **「母カバ（横向き・全身）」**（今の制作「緑のアラビア」の主役）。画面の大きさ 1600×900・背景色・色の組を固定する。品質の目標を、見て確かめられる項目で書く（少ない点・図形から・1部品1色・光と影は別の部品・口やしわは線・キャラクターっぽくしすぎず実物の特徴を捉える・少しかわいい・不快感がない、など。`docs/refs/sozai_kimari.md` と `docs/refs/jitsubutsu/カバ/` の実物の写真を参考に。**他人のイラストをなぞる物にはしない**）
3. **AI の成果物 `ai/`**：同じデータの形（描く画面で読める JSON）で、担当が作る
   - `shitagumi.json`：下組み（図形と少ない点で、大きな形と主な部品まで。細部は人に残す）
   - `ai_only.json`：AI だけで仕上げた物。**自分で描いて画像にして見直し、直す**（上限3周。目標の項目に照らす。見直しの記録を `ai/review.md` に）
   - 描く画面と同じ描き方で画像にして確かめること
4. **3つの作り方の切りかえと、見比べの画面**
   - 画面の上で「①人のみ」「②下組み＋人」「③AI のみ」を切りかえる。①は空から、②は `shitagumi.json` を読みこんで始まる（元の下組みは別に残し、どこを直したかが分かる）、③は見るだけ
   - **見比べの画面**：3つを同じ大きさ・同じ背景で横に並べる。部品の数・部品ごとの点の数・かかった時間・操作の数を並べる。拡大して輪郭を見られる
   - **評価の欄**：目標の項目ごとに、3つそれぞれへ点（1〜5）とひとことを入れられ、最後に「評価.json」（3つの絵のデータ・数字・評価・操作の記録を1つにまとめた物）として書き出せる。作り手はそれをチャットに添付して返す
5. **`使い方.md`**：Mac で、どこを開いて、どこを押すかを1つずつ。評価してほしい順番と、「評価.json」を書き出して送る所まで
6. **`RESULTS.md`**：①成果物 ②確かめた結果 ③まだ解けていないこと ④本番に採る前に評価が要ること。外部ライブラリの当たり（形の合成や曲線の計算を、既存のライブラリで行うか自前で書くか。使っていない物も、候補と使用の条件を書く）

## 決まり
- 画面の言葉は日本語。専門用語より「どこを押すか」。ボタンを押してもスクロール位置が戻らないこと
- **`localStorage` の `gh_` で始まる項目に触らない。GitHub の API を呼ばない。外部のスクリプト・字・画像を実行時に読みこまない**
- `lab/p4/` の外は変えない
- 自分で確かめる：裏で動かすブラウザ（Python の playwright。Chromium あり）で、ペンで形を描く・取っ手を動かす・図形を置く・保存して読みこむ・見比べの画面・評価の書き出し、を実際に操作して試す。JS のエラーが出ないこと。画面を PNG にして、自分で見て確かめる
- ページは GitHub Pages（`…/seisakushitsu/lab/p4/`）でも、ファイルを直接開いても動くこと

## 終わり方
**作り手が Mac で操作して評価できる状態になったら、そこで止まる。** 最後の報告（日本語・短く）：作ったファイル／自分で確かめたことと結果／確かめられなかったこと／AI の下組みと AI のみの出来についての正直な評価／作り手にしてもらうこと／push できたか（コミットの番号）。
