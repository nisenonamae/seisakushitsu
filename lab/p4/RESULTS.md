### データの形（`docs/rebuild/DATA_MODEL.md` 4節に寄せた。違う所は下）
```
doc  = { kind:'lab-p4-doc', v:1, w, h, bg, nodes:[…] }        並びの後ろほど手前
node = { id, name, kind:'shape'|'line'|'group', parent, visible, locked,
         geo: {t:'path', pts:[Pt], closed} | {t:'ellipse', size:[w,h]} | {t:'rect', size, round} | {t:'capsule', len, w},
         xf: {pos:[x,y], rot:度}（図形だけ）, fill:'#hex'|null, stroke:{c,w,cap}|null }
Pt   = { id, p:[x,y], in?:[dx,dy], out?:[dx,dy], corner?:true }   in/out が無ければ自動（HND）
```
設計との違い：`order`（Rank）でなく並びの順／自由な形は `xf` を持たず、点が画面の座標／`Value`（鍵・式）なし／色は hex だけ／グループは変形を持たない（選ぶ・隠す・固定のまとまり）。

## ③ まだ解けていないこと
1. **いちばん大事な問い「作り手の手で、質が出るか」は、まだ答えが無い。** 作り手の評価待ち
2. **AI のみの出来は、目標に届いていない**（`ai/review.md`）。点は少なく輪郭はなめらかだが、図形を並べた感じが残り、腹のピンク・脚・顔が弱い。数値だけで形を書き、画像で見て直すやり方の限界が出ている
3. **形で切り抜く（マスク）・形の合成（足す・くり抜く）が無い。** 「胴の中だけに腹の色を塗る」が、人の手ではきれいにできない（AI のみは、同じ曲線を数値で写して逃げた）。kurzgesagt 風の「光と影を別の部品で重ねる」には、ほぼ必須と見ている
4. 線の先を細くする（taper）・線を面に変える・点をそろえる（整列）・吸いつき（スナップ）・定規・対称のまま直す（写しでなく、生きた対称）は無い
5. 一覧は、引いて並べかえできない（ボタンと ］［ だけ）。グループは入れ子にできない・変形を持たない
6. 回した図形を、縦横ばらばらに伸ばすと、ゆがみ（斜めのつぶれ）は捨てて近い形にしている
7. 取り消しは、絵まるごとの控え（300回まで）。命令の形（P3a）ではない。「②の元の下組みとの違い」は、部品ごとの有り無し・変わったか、まで（点ごとではない）
8. AI の時間は計っていない（①②と時間で比べられない）

## ④ 本番に採る前に評価が要ること
- 作り手の評価（「評価.json」）：3通りの点・「この道具なら質が出る」と言えるか・足りない物が、道具／慣れ／AI の下組み／手本の分析、のどれか
- 手本（kurzgesagt）と並べての確認（ロードマップの合格条件2）。この試作の中には手本の画像を入れていない
- **取っ手の持ち方**：「無ければ自動（HND）」と「数値で持つ」の混在は、少ない点で長い曲線を作るのに合っていたか。自動の取っ手は、となりの点を動かすと曲がり方も変わる（良い面と、思わぬ変化の両方）
- 図形を数値のまま持つこと（あとで丸み・太さを変えられる）と、「自由な形に変える」の一方通行でよいか
- 操作の記録の形が、P3a の命令にそのまま流せるか（`prop.nudge` の行列、`pen.*`・`seisho` の扱い）
- 描く部品（P1：Canvas 2D／CanvasKit）と、この画面の描き方（Canvas 2D の Path2D）の一致

### 外部ライブラリの当たり（どれも、この試作では使っていない。版・使用の条件は **要確認**＝記憶で書いた。採る前に公式で確かめる）
| したいこと | 候補 | 使用の条件（要確認） | 見立て |
|---|---|---|---|
| 形の合成（足す・くり抜く・重なり）を曲線のまま | Skia の PathOps（CanvasKit / PathKit の wasm） | BSD 3条項 | **第一候補**。P1 が CanvasKit を採るなら、追加の荷物なしで使える。曲線のまま結果が返る。wasm が数MB ある |
| 同上 | Paper.js（`unite`・`subtract`・`intersect`、`simplify`） | MIT | 第二候補。素の JS で入れやすい。独自の場面の仕組みごと入るので、形の計算だけを借りる使い方になる。更新はゆっくり |
| 多角形での合成 | Clipper2（の JS 版）・polygon-clipping | Boost 1.0／MIT | 曲線を折れ線にしてから合成 → 点が増える。「少ない点」の目標に逆らうので、清書とセットでないと使えない |
| 曲線の計算（長さ・いちばん近い所・交点・ずらす） | Bezier.js（Pomax） | MIT | 小さくて確か。ずらす（offset）・交点が要るようになったら借りる。今の「近い所・割る」は自前で足りている |
| 点を減らす（清書） | fit-curve・Paper.js の `simplify`（どちらも Schneider の方法） | MIT | **自前で書いた**（`geom.js` の `seisho`。約80行）。角を残す・輪を閉じる所を自分の形に合わせたかったため。借りる必要は薄い |
| 線を面にする・太さの変わる線 | Skia（PathOps・stroker）／perfect-freehand | BSD／MIT | 線の先を細くするなら要る。今は太さ一定の線だけなので不要 |

**当たり**：点と取っ手・図形・清書は自前で足りる（合わせて約350行）。**形の合成と切り抜きだけは自前で書かない**（交点の扱いが難しく、まちがいが出やすい）。P1 の結果が CanvasKit なら PathOps、Canvas 2D なら Paper.js の計算だけ借りる、の2択で次に試すのがよい。切り抜き（マスク）は、合成より先に、描くときの切り抜き（Canvas の `clip`）で試せる。
