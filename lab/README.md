# lab：作り直しの試作（捨ててよい物）

`docs/rebuild/` の設計を確かめるための試作の置き場。**今の制作室の実装とは別物**で、ここの物を本番にそのまま使うとは決めていない（採る前に必ず評価する）。

| フォルダ | 試作 | 何を確かめるか |
|---|---|---|
| `p4/` | 曲線の画面 | 作り手の手で、質の高い部品が作れるか。人のみ／AI の下組み＋人／AI のみ を、同じ題材・同じ目標で比べる |
| `p3a/` | 命令の核 | 命令の適用・検査・取り消し・AI の変更だけを選んで戻す。画面も通信もなし |
| `p1/` | 描く部品 | Canvas 2D と CanvasKit の、絵の質・速さ・下見と書き出しの一致 |

## 全部の試作で守ること
1. **自分のフォルダ（`lab/pX/`）の外のファイルを変えない・消さない。** 今の制作室（`*.html`・`tools/`・`data/`・`docs/`・`sw.js` など）には触らない。読むのはよい。
2. **認証トークンに触らない。** `localStorage` の `gh_` で始まる項目を読まない・書かない。GitHub の API を呼ばない。保存に使う名前は `lab:pX:` で始める。
3. **外部のスクリプト・字・画像を、実行時に外から読みこまない。** 要る物は自分のフォルダに置く（`vendor/`）。出どころ・版・使用の条件を記録する。
4. `node_modules` などはコミットしない。
5. **記録を残す**：各フォルダの `RESULTS.md` に、①成果物 ②確かめた結果（数字・画像）③まだ解けていないこと ④本番に採る前に評価が要ること。確かめていないことは「未確認」と書く。
6. 画面の言葉は日本語。専門用語より、どこを押すかが分かる言葉で。ボタンを押してもスクロール位置が戻らないこと。
7. push はまとめる（公開の組み立ては1時間に10回がゆるい上限）。コミットするのは自分のフォルダだけ。
